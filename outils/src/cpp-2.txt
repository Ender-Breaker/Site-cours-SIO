=== cpp-pointeurs | C++ : pointeurs et mémoire | d
Les pointeurs sont ce qui distingue vraiment le C++ : ils donnent un accès direct à la **mémoire**. C'est la notion qui fait peur, alors qu'elle se résume à une idée : une variable peut contenir **l'adresse** d'une autre.

## 1. Adresse et pointeur

Chaque variable occupe une case de la mémoire, repérée par une **adresse**. L'opérateur `&` donne cette adresse ; un **pointeur** est une variable qui la stocke.

```run h=iostream main
int age = 17;
int* p = &age;             // p contient l'adresse de age : « p pointe sur age »
cout << age << endl;       // 17
cout << (p == &age) << endl;   // 1 : même adresse
cout << *p << endl;        // 17 : *p = la valeur à l'adresse pointée
*p = 18;                   // modifie age à travers le pointeur
cout << age << endl;       // 18
```

| Écriture | Signifie |
| `int* p` | p est un pointeur vers un `int` |
| `&x` | l'adresse de x |
| `*p` | la valeur à l'adresse contenue dans p (*déréférencement*) |
| `nullptr` | le pointeur qui ne pointe sur rien |

## 2. `nullptr` et les pointeurs dangereux

```run h=iostream main
int* p = nullptr;            // toujours initialiser un pointeur
if (p == nullptr) cout << "p ne pointe sur rien" << endl;
int x = 5;
p = &x;
if (p) cout << "p pointe sur " << *p << endl;     // if (p) : vrai si non nul
```

!attention Déréférencer nullptr | Écrire `*p` quand `p` vaut `nullptr`, ou quand il pointe sur une variable qui n'existe plus, est un **comportement indéfini** : le programme plante (*segmentation fault*) ou, pire, continue avec des données fausses. Teste toujours un pointeur avant de l'utiliser.

## 3. Pointeur ou référence ?

Les deux permettent à une fonction d'agir sur une variable de l'appelant.

```run h=iostream main
void parReference(int& n) { n = n + 1; }
void parPointeur(int* n) { if (n) *n = *n + 1; }
@@
int x = 10;
parReference(x);           // rien de spécial à l'appel
parPointeur(&x);           // on passe l'adresse
cout << x << endl;
parPointeur(nullptr);      // un pointeur peut être nul : la fonction doit le prévoir
```

| | Référence `int&` | Pointeur `int*` |
| Peut ne désigner rien | non | oui (`nullptr`) |
| Peut changer de cible | non | oui |
| Syntaxe d'accès | comme une variable | `*p`, `p->membre` |
| À utiliser | par défaut | quand « rien » est possible, ou pour la mémoire dynamique |

## 4. Pointeurs et tableaux

Le nom d'un tableau C se comporte comme un pointeur vers son premier élément, et `p + 1` désigne l'élément suivant.

```run h=iostream main
int t[4] = {10, 20, 30, 40};
int* p = t;                          // pointe sur t[0]
cout << *p << " " << *(p + 2) << " " << p[3] << endl;   // p[i] équivaut à *(p + i)
for (int* q = t; q != t + 4; q++) cout << *q << " ";    // parcours par pointeur
cout << endl;
```

C'est exactement le principe des itérateurs `begin()` et `end()` des conteneurs.

## 5. La pile et le tas

| | La pile (*stack*) | Le tas (*heap*) |
| Contient | les variables locales | ce qu'on réserve avec `new` |
| Libération | automatique, à la fin du bloc | manuelle, avec `delete` |
| Taille | petite et fixe | grande |
| Durée de vie | celle du bloc | jusqu'au `delete` |

```run h=iostream main
int* p = new int(42);          // réserve un int sur le tas
cout << *p << endl;
delete p;                      // libère : obligatoire
p = nullptr;                   // bonne habitude : ne plus pointer sur la zone libérée

int n = 5;
int* tab = new int[n];         // tableau de taille connue à l'exécution
for (int i = 0; i < n; i++) tab[i] = i * i;
cout << tab[4] << endl;
delete[] tab;                  // delete[] pour un tableau
```

Les trois erreurs classiques :

- **fuite de mémoire** : un `new` sans `delete` ; la mémoire reste occupée jusqu'à la fin du programme ;
- **pointeur pendant** (*dangling*) : utiliser un pointeur après le `delete`, ou renvoyer l'adresse d'une variable locale ;
- **double libération** : deux `delete` sur la même adresse.

!info En C++ moderne | On n'écrit presque plus `new` et `delete` à la main : `vector` gère sa mémoire tout seul, et les **pointeurs intelligents** (chapitre « Mémoire moderne ») libèrent automatiquement. Il faut pourtant comprendre ce mécanisme : il est sous tout le reste.

## 6. Pointeurs vers des structures : `->`

```run h=iostream,string main
struct Joueur {
    string nom;
    int pv;
};
@@
Joueur j = {"Léa", 10};
Joueur* p = &j;
cout << (*p).nom << endl;      // écriture lourde…
cout << p->nom << endl;        // … remplacée par la flèche
p->pv -= 3;
cout << j.pv << endl;
```

    return true;
}
@@

if (!diviser(1, 0, &r)) cout << "division impossible" << endl;

=== cpp-classes | C++ : classes et objets | d
Une **classe** regroupe des données (les **attributs**) et les fonctions qui agissent dessus (les **méthodes**). Un **objet** est un exemplaire de cette classe.

## 1. D'abord `struct` : regrouper des données

```run h=iostream,string,vector main
struct Produit {
    string nom;
    double prix;
    int stock = 0;                 // valeur par défaut
};
@@
Produit p = {"Souris", 19.9, 4};
Produit q;                         // nom vide, prix indéterminé, stock 0
q.nom = "Clavier";
q.prix = 49;
vector<Produit> catalogue = {p, q};
for (const Produit& x : catalogue) {
    cout << x.nom << " : " << x.prix << " € (" << x.stock << ")" << endl;
}
```

## 2. Une classe : données privées, méthodes publiques

```run h=iostream,string main
class Compte {
private:                               // inaccessible de l'extérieur
    string titulaire;
    double solde;

public:                                // l'interface de la classe
    Compte(const string& t, double s) : titulaire(t), solde(s) {}   // constructeur

    void deposer(double montant) {
        if (montant > 0) solde += montant;
    }
    bool retirer(double montant) {
        if (montant > solde) return false;
        solde -= montant;
        return true;
    }
    double getSolde() const { return solde; }      // const : ne modifie pas l'objet
};
@@
Compte c("Léa", 100);
c.deposer(50);
cout << c.retirer(500) << " " << c.retirer(30) << endl;
cout << c.getSolde() << endl;
// c.solde = 1000000;   // refusé à la compilation : solde est privé
```

C'est l'**encapsulation** : l'état de l'objet n'est modifiable que par ses méthodes, qui garantissent qu'il reste cohérent (ici, jamais de solde négatif).

| Mot-clé | Accès |
| `public` | depuis partout |
| `private` | depuis la classe uniquement (par défaut dans une `class`) |
| `protected` | depuis la classe et ses classes filles |

La seule différence entre `struct` et `class` : dans une `struct` tout est public par défaut, dans une `class` tout est privé par défaut.

## 3. Constructeurs

Le **constructeur** porte le nom de la classe et n'a pas de type de retour. Il est appelé automatiquement à la création de l'objet. La **liste d'initialisation** (après les deux-points) donne leur valeur aux attributs.

```run h=iostream,string main
class Point {
public:
    double x, y;
    Point() : x(0), y(0) {}                          // constructeur par défaut
    Point(double x, double y) : x(x), y(y) {}        // constructeur à deux paramètres
};
@@
Point a;                 // appelle Point()
Point b(3, 4);           // appelle Point(double, double)
Point c{5, 6};           // écriture avec accolades, équivalente
cout << a.x << " " << b.y << " " << c.x << endl;
```

## 4. Méthodes `const`, `this`, membres `static`

```run h=iostream,string main
class Joueur {
    string nom;
    int pv;
    static int nombre;                       // partagé par TOUS les joueurs
public:
    Joueur(const string& nom, int pv) : nom(nom), pv(pv) { nombre++; }

    Joueur& blesser(int degats) {
        this->pv -= degats;                  // this : pointeur vers l'objet courant
        if (pv < 0) pv = 0;
        return *this;                        // permet d'enchaîner les appels
    }
    bool estVivant() const { return pv > 0; }      // promet de ne rien modifier
    int getPv() const { return pv; }
    static int combien() { return nombre; }        // appelée sans objet
};
int Joueur::nombre = 0;                      // définition du membre static
@@
Joueur a("Léa", 10), b("Sam", 5);
a.blesser(3).blesser(2);                     // enchaînement grâce à return *this
b.blesser(99);
cout << a.getPv() << " " << b.estVivant() << " " << Joueur::combien() << endl;
```

!attention Marque `const` tout ce qui ne modifie rien | Un objet reçu par `const Joueur&` ne peut appeler **que** des méthodes `const`. Oublier le `const` sur un accesseur provoque des erreurs de compilation plus loin, là où on s'y attend le moins.

## 5. Le destructeur

Le **destructeur** (`~NomDeLaClasse`) est appelé automatiquement quand l'objet est détruit : à la fin de son bloc pour une variable locale. Il sert à libérer ce que l'objet a réservé.

```run h=iostream,string main
class Fichier {
    string nom;
public:
    Fichier(const string& n) : nom(n) { cout << "ouverture de " << nom << endl; }
    ~Fichier() { cout << "fermeture de " << nom << endl; }
};
@@
Fichier a("a.txt");
{
    Fichier b("b.txt");
    cout << "fin du bloc" << endl;
}                                  // b est détruit ici
cout << "fin de main" << endl;
```

## 6. `enum class` : une liste de valeurs nommées

```run h=iostream main
enum class Etat { Menu, Jeu, Pause, Fin };
@@
Etat e = Etat::Jeu;
if (e == Etat::Jeu) cout << "en jeu" << endl;
switch (e) {
    case Etat::Menu: cout << "menu" << endl; break;
    case Etat::Jeu:  cout << "partie en cours" << endl; break;
    default:         cout << "autre" << endl;
}
cout << static_cast<int>(Etat::Pause) << endl;     // 2 : numérotés à partir de 0
```

=== cpp-heritage | C++ : héritage et polymorphisme | d
## 1. Hériter d'une classe

Une classe **fille** (ou dérivée) reprend les attributs et les méthodes de sa classe **mère** (ou de base), et peut en ajouter.

```run h=iostream,string main
class Personnage {
protected:                          // accessible aux classes filles
    string nom;
    int pv;
public:
    Personnage(const string& nom, int pv) : nom(nom), pv(pv) {}
    void blesser(int d) { pv -= d; if (pv < 0) pv = 0; }
    void afficher() const { cout << nom << " : " << pv << " PV" << endl; }
};

class Guerrier : public Personnage {              // Guerrier EST UN Personnage
    int force;
public:
    Guerrier(const string& nom, int force)
        : Personnage(nom, 20), force(force) {}    // appelle d'abord le constructeur de la mère
    void frapper(Personnage& cible) { cible.blesser(force); }
};
@@
Guerrier g("Conan", 7);
Personnage p("Gobelin", 10);
g.frapper(p);
g.afficher();            // méthode héritée
p.afficher();
```

L'héritage exprime une relation **« est un »** : un Guerrier est un Personnage. Si la relation est « a un » (une voiture **a un** moteur), on utilise un attribut, pas l'héritage.

## 2. Redéfinir une méthode : `virtual` et `override`

```run h=iostream,string main
class Animal {
protected:
    string nom;
public:
    Animal(const string& nom) : nom(nom) {}
    virtual string crier() const { return "..."; }       // virtual : redéfinissable
    void presenter() const { cout << nom << " fait " << crier() << endl; }
    virtual ~Animal() = default;                         // destructeur virtuel : voir plus bas
};

class Chien : public Animal {
public:
    Chien(const string& nom) : Animal(nom) {}
    string crier() const override { return "Ouaf"; }     // override : vérifié par le compilateur
};

class Chat : public Animal {
public:
    using Animal::Animal;                                // réutilise les constructeurs de la mère
    string crier() const override { return "Miaou"; }
};
@@
Chien rex("Rex");
Chat tigrou("Tigrou");
rex.presenter();
tigrou.presenter();
```

`presenter` est écrite une seule fois dans `Animal`, mais appelle le `crier` de la **vraie** classe de l'objet : c'est le **polymorphisme**.

!attention Sans `virtual`, pas de polymorphisme | Si `crier` n'est pas `virtual` dans la classe mère, c'est toujours la version de la mère qui est appelée à travers une référence ou un pointeur de type `Animal`. Et sans `override`, une faute de frappe dans la signature crée silencieusement une **nouvelle** méthode au lieu de redéfinir l'ancienne.

## 3. Le polymorphisme passe par les pointeurs et les références

```run h=iostream,string,vector main
class Forme {
public:
    virtual double aire() const = 0;       // = 0 : méthode virtuelle PURE
    virtual string nom() const = 0;
    virtual ~Forme() = default;
};

class Rectangle : public Forme {
    double l, h;
public:
    Rectangle(double l, double h) : l(l), h(h) {}
    double aire() const override { return l * h; }
    string nom() const override { return "rectangle"; }
};

class Cercle : public Forme {
    double r;
public:
    Cercle(double r) : r(r) {}
    double aire() const override { return 3.14159 * r * r; }
    string nom() const override { return "cercle"; }
};

void decrire(const Forme& f) {             // accepte n'importe quelle Forme
    cout << f.nom() << " d'aire " << f.aire() << endl;
}
@@
Rectangle r(3, 4);
Cercle c(1);
decrire(r);
decrire(c);

vector<Forme*> formes = {&r, &c};          // une collection de formes différentes
double total = 0;
for (const Forme* f : formes) total += f->aire();
cout << "Aire totale : " << total << endl;
```

Une classe qui possède au moins une méthode virtuelle pure est **abstraite** : on ne peut pas créer d'objet `Forme`, seulement des objets de ses classes filles. C'est l'équivalent d'une **interface**.

!attention Le découpage (*slicing*) | `vector<Forme>` ne peut pas contenir des rectangles : copier un `Rectangle` dans une variable de type `Forme` ne garde que la partie mère. Pour le polymorphisme, il faut toujours des **pointeurs** ou des **références**.

## 4. Appeler la version de la mère

```run h=iostream,string main
class Employe {
protected:
    string nom;
    double salaire;
public:
    Employe(const string& n, double s) : nom(n), salaire(s) {}
    virtual double paie() const { return salaire; }
    virtual ~Employe() = default;
};

class Commercial : public Employe {
    double ventes;
public:
    Commercial(const string& n, double s, double v) : Employe(n, s), ventes(v) {}

    }
};
@@

```

## 5. Pourquoi un destructeur virtuel ?

Quand on détruit un objet de classe fille à travers un pointeur de la classe mère, seul un destructeur `virtual` garantit que le destructeur de la fille est appelé. Règle simple : **une classe avec au moins une méthode virtuelle a un destructeur virtuel**.

```run h=iostream main
class Base {
public:
    virtual ~Base() { cout << "destruction de Base" << endl; }
};
class Derivee : public Base {
public:
    ~Derivee() override { cout << "destruction de Derivee" << endl; }
};
@@
Base* p = new Derivee();
delete p;              // appelle ~Derivee puis ~Base grâce à virtual
```

=== cpp-memoire-moderne | C++ : RAII, copie et pointeurs intelligents | d
Le C++ moderne (depuis C++11) permet de ne **presque jamais** écrire `delete`. Le principe qui rend cela possible s'appelle **RAII**.

## 1. RAII : la ressource vit avec l'objet

*Resource Acquisition Is Initialization* : une ressource (mémoire, fichier, connexion, verrou) est **acquise dans le constructeur** et **libérée dans le destructeur**. Comme le destructeur d'une variable locale est toujours appelé à la fin de son bloc, la ressource est toujours libérée, même si on quitte la fonction au milieu.

```run h=iostream,string main
class Connexion {
    string serveur;
public:
    Connexion(const string& s) : serveur(s) { cout << "connexion à " << serveur << endl; }
    ~Connexion() { cout << "déconnexion de " << serveur << endl; }
    void requete(const string& q) const { cout << "  requête : " << q << endl; }
};

void travail(bool erreur) {
    Connexion c("bdd.local");
    c.requete("SELECT 1");
    if (erreur) return;                 // sortie anticipée : c est quand même détruit
    c.requete("SELECT 2");
}
@@
travail(false);
travail(true);
```

`vector`, `string`, `ifstream` fonctionnent tous ainsi : c'est pour cela qu'on ne libère jamais leur mémoire à la main.

## 2. `unique_ptr` : un seul propriétaire

`unique_ptr<T>` (bibliothèque `<memory>`) possède un objet créé sur le tas et le détruit automatiquement. Il ne peut pas être copié, seulement **déplacé**.

```run h=iostream,memory,string main
struct Arme {
    string nom;
    Arme(const string& n) : nom(n) { cout << "création de " << nom << endl; }
    ~Arme() { cout << "destruction de " << nom << endl; }
};
@@
unique_ptr<Arme> a = make_unique<Arme>("épée");     // jamais de new
cout << a->nom << endl;                              // s'utilise comme un pointeur
// unique_ptr<Arme> b = a;                           // refusé : copie interdite
unique_ptr<Arme> b = move(a);                        // transfert de propriété
cout << (a == nullptr) << " " << b->nom << endl;     // a est vide
cout << "fin de main" << endl;                       // l'épée est détruite ici, toute seule
```

C'est aussi la bonne façon de stocker des objets polymorphes :

```run h=iostream,memory,vector,string main
struct Forme {
    virtual double aire() const = 0;
    virtual ~Forme() = default;
};
struct Carre : Forme {
    double c;
    Carre(double c) : c(c) {}
    double aire() const override { return c * c; }
};
struct Disque : Forme {
    double r;
    Disque(double r) : r(r) {}
    double aire() const override { return 3.14159 * r * r; }
};
@@
vector<unique_ptr<Forme>> formes;
formes.push_back(make_unique<Carre>(2));
formes.push_back(make_unique<Disque>(1));
for (const auto& f : formes) cout << f->aire() << endl;
// tout est libéré automatiquement à la fin
```

## 3. `shared_ptr` : plusieurs propriétaires

`shared_ptr<T>` compte ses propriétaires ; l'objet est détruit quand le dernier disparaît.

```run h=iostream,memory,string main
struct Texture {
    string fichier;
    Texture(const string& f) : fichier(f) { cout << "chargement de " << fichier << endl; }
    ~Texture() { cout << "libération de " << fichier << endl; }
};
@@
shared_ptr<Texture> a = make_shared<Texture>("herbe.png");
cout << a.use_count() << endl;            // 1 propriétaire
{
    shared_ptr<Texture> b = a;            // copie autorisée : 2 propriétaires
    cout << a.use_count() << endl;
}                                         // b disparaît : retour à 1
cout << a.use_count() << endl;
a.reset();                                // plus aucun propriétaire : libération
cout << "fin" << endl;
```

| | `unique_ptr` | `shared_ptr` | Pointeur brut `T*` |
| Propriétaires | un seul | plusieurs (compteur) | aucun : il **observe** |
| Copie | interdite (`move`) | autorisée | autorisée |
| Libération | automatique | automatique, au dernier | jamais |
| À utiliser | par défaut | ressource réellement partagée | paramètre de fonction, sans propriété |

## 4. La copie d'un objet

Par défaut, copier un objet copie chacun de ses attributs. C'est parfait… sauf si un attribut est un pointeur brut : les deux objets pointent alors sur la même zone, et chacun la libérera (double libération). D'où la **règle de zéro** : utilise `vector`, `string` et les pointeurs intelligents comme attributs, et tu n'auras **aucun** destructeur ni constructeur de copie à écrire.

```run h=iostream,vector,string main
class Classe {
    string nom;
    vector<string> eleves;         // gère sa mémoire tout seul
public:
    Classe(const string& n) : nom(n) {}
    void ajouter(const string& e) { eleves.push_back(e); }
    size_t effectif() const { return eleves.size(); }
};
@@
Classe a("SIO1");
a.ajouter("Léa");
Classe b = a;                      // copie complète et indépendante, sans rien écrire
b.ajouter("Sam");
cout << a.effectif() << " " << b.effectif() << endl;
```

## 5. Déplacer au lieu de copier : `std::move`

Copier un gros vector recopie tous ses éléments. Le **déplacer** transfère simplement son contenu vers le destinataire ; l'objet d'origine reste valide, mais vide.

```run h=iostream,vector,string,utility main
vector<string> source = {"a", "b", "c"};
vector<string> copie = source;              // copie : 3 chaînes recopiées
vector<string> deplace = move(source);      // déplacement : aucune recopie
cout << copie.size() << " " << deplace.size() << " " << source.size() << endl;
```

!info La règle de trois, cinq, zéro | Si ta classe gère elle-même une ressource brute et a besoin d'un destructeur, elle a aussi besoin d'un constructeur de copie et d'un opérateur d'affectation (**règle de trois**), plus leurs versions par déplacement (**règle de cinq**). La meilleure solution reste de n'en écrire aucun (**règle de zéro**).

=== cyber-panorama | Cybersécurité : les bases, le vocabulaire et la loi | f
La **cybersécurité** protège les systèmes, les réseaux et les données contre les accès non autorisés, les pannes provoquées et les vols. C'est le bloc 3 du BTS SIO, commun aux deux options, et l'un des secteurs qui recrutent le plus. Pour bien défendre, il faut comprendre comment on attaque : c'est le fil de ce cours.

!attention Le cadre légal d'abord | En France, accéder ou se maintenir **sans autorisation** dans un système est un délit, même sans rien casser et même « pour aider » : jusqu'à 3 ans de prison et 100 000 € d'amende (article 323-1 du Code pénal), davantage si des données sont modifiées ou si le système appartient à l'État. Tout ce que tu apprends ici se pratique **uniquement** sur tes propres machines, dans les labos de ce site, ou sur des plateformes prévues pour cela (Root-Me, TryHackMe, Hack The Box, les CTF).

## 1. Les trois piliers : D, I, C

| Pilier | Question | Exemple d'atteinte |
| **D**isponibilité | le service répond-il quand on en a besoin ? | site saturé par un déni de service, fichiers chiffrés par un rançongiciel |
| **I**ntégrité | les données sont-elles exactes, non modifiées ? | une note changée dans la base, un virement détourné |
| **C**onfidentialité | seules les bonnes personnes y ont-elles accès ? | fuite d'une base de clients |

On ajoute souvent la **traçabilité** (ou preuve) : savoir qui a fait quoi, et quand. En anglais, on parle de la triade **CIA** (*Confidentiality, Integrity, Availability*).

## 2. Vulnérabilité, menace, risque

| Terme | Définition | Exemple |
| **Actif** | ce qui a de la valeur | la base des clients |
| **Vulnérabilité** | une faiblesse | un serveur pas mis à jour |
| **Menace** | ce qui peut exploiter la faiblesse | un groupe de rançongiciel |
| **Risque** | probabilité × impact | forte chance d'être chiffré, arrêt de l'activité |
| **Exploit** | le moyen technique d'utiliser une vulnérabilité | |
| **Correctif** (*patch*) | la mise à jour qui supprime la vulnérabilité | |

On ne peut pas supprimer tous les risques : on les **réduit** (protections), on les **transfère** (assurance), on les **évite** (ne pas proposer le service), ou on les **accepte** en connaissance de cause.

Les vulnérabilités connues portent un identifiant **CVE** (par exemple CVE-2021-44228, « Log4Shell ») et une note de gravité **CVSS** de 0 à 10.

```run
// Un calcul de risque simplifié, comme dans une analyse de risques
const risques = [
  { nom: "Rançongiciel sur le serveur de fichiers", probabilite: 3, impact: 4 },
  { nom: "Vol d'un ordinateur portable non chiffré", probabilite: 2, impact: 3 },
  { nom: "Panne de courant", probabilite: 1, impact: 2 },
];
for (const r of risques.sort((a, b) => b.probabilite * b.impact - a.probabilite * a.impact)) {
  console.log(`${r.probabilite * r.impact}  ${r.nom}`);
}
```

## 3. Qui attaque, et pourquoi ?

| Acteur | Motivation |
| Cybercriminels | l'argent : rançons, revente de données, fraude |
| États et groupes soutenus par des États | espionnage, sabotage |
| Hacktivistes | une cause politique |
| Concurrents | espionnage industriel |
| Menace interne | vengeance, négligence, erreur d'un employé |
| Curieux (*script kiddies*) | le défi, avec des outils tout faits |

La plupart des attaques ne visent personne en particulier : des robots balaient Internet à la recherche de la moindre machine vulnérable. « Je n'intéresse personne » n'est pas une protection.

## 4. Les « chapeaux » et les équipes

| Nom | Rôle |
| *White hat* (hacker éthique) | cherche des failles **avec autorisation**, pour les faire corriger |
| *Black hat* | attaque sans autorisation, à des fins malveillantes |
| *Grey hat* | sans autorisation mais sans intention de nuire : **illégal quand même** |
| *Red team* | l'équipe qui joue l'attaquant lors d'un exercice |
| *Blue team* | l'équipe qui défend et détecte |
| *Purple team* | les deux équipes qui travaillent ensemble |

## 5. Le déroulement d'une attaque

Une attaque sérieuse suit des étapes, que décrivent des modèles comme la *Cyber Kill Chain* ou la matrice **MITRE ATT&CK** :

1. **Reconnaissance** : collecter des informations sur la cible (site, employés, technologies).
2. **Accès initial** : hameçonnage, mot de passe faible, faille d'un service exposé.
3. **Exécution et persistance** : installer de quoi revenir.
4. **Élévation de privilèges** : passer d'un compte ordinaire à un compte administrateur.
5. **Déplacement latéral** : rebondir de machine en machine.
6. **Action finale** : vol de données, chiffrement, sabotage.

Chaque étape est une occasion de **détecter et de bloquer** : c'est le principe de la défense en profondeur. Tu peux t'y exercer dans le [duel attaque / défense](duel.html).

## 6. Les textes à connaître

| Texte | Ce qu'il impose |
| Code pénal, art. 323-1 à 323-8 | interdit l'intrusion, l'entrave, la modification de données, et la détention d'outils sans motif légitime |
| **RGPD** | protéger les données personnelles ; notifier la **CNIL sous 72 heures** en cas de violation |
| Directive **NIS 2** | obligations de sécurité pour les entités essentielles et importantes |
| Charte informatique | les règles d'usage dans l'entreprise ou le lycée |

Les organismes de référence : l'**ANSSI** (agence nationale, guides et certifications), la **CNIL** (données personnelles), **cybermalveillance.gouv.fr** (assistance aux victimes), le **CERT-FR** (alertes).

## 7. Les métiers

| Métier | Mission |
| Analyste SOC | surveiller les alertes et qualifier les incidents |
| Pentesteur (auditeur) | tester la sécurité avec autorisation et rédiger un rapport |
| Administrateur sécurité | pare-feu, sauvegardes, durcissement, correctifs |
| Analyste en réponse à incident (CSIRT) | enquêter et remettre en état après une attaque |
| Développeur sécurité (DevSecOps) | intégrer la sécurité dans le code et le déploiement |
| RSSI | piloter la sécurité de l'organisation |
| DPO | veiller au respect du RGPD |

=== cyber-attaques | Cybersécurité : les grandes familles d'attaques | m
Ce chapitre fait le tour des attaques que tu dois savoir **reconnaître**. Pour chacune : le principe, les signes qui la trahissent, et la parade. Les attaques propres aux sites web (injection SQL, XSS, CSRF) ont leur propre chapitre.

## 1. Les logiciels malveillants (*malwares*)

| Type | Ce qu'il fait | Comment il arrive |
| **Virus** | s'attache à un fichier et se propage quand on l'ouvre | pièce jointe, téléchargement |
| **Ver** (*worm*) | se propage **seul** par le réseau | faille d'un service exposé |
| **Cheval de Troie** | se fait passer pour un logiciel utile | faux logiciel, logiciel piraté |
| **Rançongiciel** (*ransomware*) | chiffre les fichiers et exige une rançon | hameçonnage, accès distant mal protégé |
| **Logiciel espion** (*spyware*), enregistreur de frappe | vole mots de passe et données | cheval de Troie |
| **Rootkit** | se cache au cœur du système | après une élévation de privilèges |
| **Botnet** | transforme la machine en « zombie » pilotée à distance | toutes les voies ci-dessus |
| **Porte dérobée** (*backdoor*) | laisse un accès secret | installée par l'attaquant |

Signes : machine lente, ventilateur qui s'emballe, fichiers renommés avec une extension inconnue, antivirus désactivé, connexions réseau vers des adresses inconnues.

Parades : mises à jour, antivirus ou **EDR**, pas de droits administrateur au quotidien, **sauvegardes hors ligne**, filtrage des pièces jointes.

!attention Face à un rançongiciel | **Débrancher** la machine du réseau (câble et Wi-Fi) sans l'éteindre, prévenir le responsable, ne pas payer (aucune garantie, et cela finance les attaquants), restaurer depuis une sauvegarde saine, porter plainte.

## 2. Les attaques sur les mots de passe

| Attaque | Principe | Parade |
| Force brute | essayer toutes les combinaisons | longueur, blocage après N échecs |
| Dictionnaire | essayer les mots de passe les plus courants | pas de mot du dictionnaire, liste noire |
| *Credential stuffing* | rejouer des couples identifiant / mot de passe volés ailleurs | un mot de passe **différent** par site, MFA |
| *Password spraying* | un seul mot de passe courant essayé sur des milliers de comptes | MFA, détection |
| Vol de la base d'empreintes | casser les empreintes hors ligne | bcrypt / Argon2 avec sel |

```run
// Pourquoi la longueur compte plus que les symboles : le nombre de combinaisons
function combinaisons(alphabet, longueur) { return Math.pow(alphabet, longueur); }
const parSeconde = 1e10;       // dix milliards d'essais par seconde (matériel spécialisé, empreintes rapides)
const duree = n => {
  const s = n / parSeconde;
  if (s < 60) return s.toFixed(1) + " secondes";
  if (s < 86400) return (s / 3600).toFixed(1) + " heures";
  if (s < 3.15e7) return (s / 86400).toFixed(0) + " jours";
  return (s / 3.15e7).toExponential(1) + " années";
};
console.log("8 minuscules           :", duree(combinaisons(26, 8)));
console.log("8 caractères variés    :", duree(combinaisons(94, 8)));
console.log("12 caractères variés   :", duree(combinaisons(94, 12)));
console.log("phrase de 20 minuscules:", duree(combinaisons(26, 20)));
```

## 3. Les attaques réseau

| Attaque | Principe | Parade |
| **Déni de service** (DoS / DDoS) | saturer un service de requêtes, souvent depuis un botnet | protection anti-DDoS, limitation de débit, CDN |
| **Homme du milieu** (MITM) | s'intercaler entre deux machines pour lire ou modifier les échanges | HTTPS, VPN, certificats vérifiés |
| **Écoute** (*sniffing*) | capturer le trafic non chiffré | chiffrement de bout en bout |
| **Usurpation** (*spoofing*) | falsifier une adresse IP, MAC, ARP ou DNS | sécurisation des commutateurs, DNSSEC |
| **Faux point d'accès Wi-Fi** | imiter un réseau connu pour capter les connexions | VPN, ne pas se connecter automatiquement |
| **Balayage de ports** | repérer les services ouverts : c'est la reconnaissance | pare-feu, fermer l'inutile, détection |

## 4. L'exploitation de vulnérabilités

| Notion | Définition |
| Faille non corrigée | la vulnérabilité est connue et un correctif existe, mais n'a pas été installé : le cas le plus fréquent |
| **Zero-day** | vulnérabilité inconnue de l'éditeur : aucun correctif n'existe encore |
| Configuration par défaut | mot de passe d'usine, page d'administration exposée, service inutile actif |
| Élévation de privilèges | passer d'un compte limité à administrateur |
| Attaque de la chaîne d'approvisionnement | piéger un logiciel ou une bibliothèque que la cible utilise |

Parade principale : **mettre à jour**, vite et partout, et réduire la surface d'attaque (ce qui n'est pas installé ne peut pas être attaqué).

## 5. La menace interne et physique

Un employé mécontent, un prestataire trop curieux, un poste laissé déverrouillé, une clé USB trouvée sur le parking et branchée par curiosité, un visiteur qui se connecte à une prise réseau libre. Parades : **moindre privilège**, verrouillage automatique des sessions, journalisation, contrôle des ports réseau (802.1X), sensibilisation.

## 6. Tableau de synthèse

| Pilier visé | Attaques typiques |
| Disponibilité | DDoS, rançongiciel, sabotage |
| Intégrité | modification de base de données, défacement de site, homme du milieu |
| Confidentialité | hameçonnage, logiciel espion, écoute, fuite de données |

# Dans un journal d'authentification
Des centaines d'échecs en quelques minutes depuis la même adresse, sur un seul compte : **force brute**.

# Dans un journal de serveur web
Des apostrophes, des mots-clés SQL ou des balises dans les paramètres : une tentative d'**injection**.
```
GET /produit.php?id=12'%20OR%20'1'='1 HTTP/1.1" 200
GET /recherche.php?q=<script>… HTTP/1.1" 200
```

Des fichiers renommés `rapport.docx.locked` et un fichier `LISEZ-MOI.txt` dans chaque dossier : **rançongiciel**. Réflexe : isoler la machine du réseau.

=== cyber-social | Cybersécurité : hameçonnage et ingénierie sociale | f
La faille la plus exploitée n'est pas technique : c'est **l'humain**. L'**ingénierie sociale** consiste à manipuler une personne pour qu'elle donne une information ou fasse une action. Plus de la moitié des intrusions commencent par un message piégé.

## 1. Les leviers psychologiques

| Levier | Exemple |
| **Urgence** | « Votre compte sera supprimé dans 24 heures » |
| **Autorité** | un message qui semble venir du directeur, de la banque, de l'administration |
| **Peur** | « Activité suspecte détectée sur votre compte » |
| **Appât du gain** | « Vous avez gagné », « remboursement en attente » |
| **Curiosité** | « Regarde cette photo de toi » |
| **Envie d'aider** | « Je suis le nouveau stagiaire, tu peux m'ouvrir ? » |

Un message qui te presse d'agir **tout de suite** doit te faire ralentir.

## 2. Les formes d'hameçonnage

| Nom | Canal |
| *Phishing* | courriel envoyé en masse |
| *Spear phishing* | courriel **ciblé**, personnalisé avec des informations sur la victime |
| *Smishing* | SMS (faux colis, faux compte de formation, fausse amende) |
| *Vishing* | appel téléphonique (faux conseiller bancaire, faux support technique) |
| *Quishing* | code QR piégé |
| Arnaque au président | un faux dirigeant demande un virement urgent et confidentiel |
| Faux support | une fenêtre « votre ordinateur est infecté, appelez ce numéro » |

## 3. Reconnaître un message piégé

| Indice | À vérifier |
| L'adresse de l'expéditeur | `service@banque-securite-fr.com` n'est pas le domaine de ta banque |
| L'adresse réelle du lien | survole-le sans cliquer : le texte affiché et la destination diffèrent |
| Le ton | urgence, menace, récompense |
| La demande | mot de passe, code reçu par SMS, coordonnées bancaires : jamais par courriel |
| La pièce jointe | `.exe`, `.js`, `.iso`, archive protégée, document qui demande d'« activer les macros » |
| La forme | fautes, salutation vague (« cher client »), logo flou |

Les noms de domaine trompeurs sont la technique reine : une lettre changée (`paypa1.com`), un sous-domaine qui fait illusion (`banque.fr.connexion-securisee.net` appartient à `connexion-securisee.net`), ou un caractère d'un autre alphabet qui ressemble à s'y méprendre.

```run
// Quel est le vrai domaine d'une adresse ? Ce qui précède le premier « / », lu de droite à gauche.
function domaine(url) {
  const hote = url.replace(/^https?:\/\//, "").split("/")[0].split("@").pop().split(":")[0];
  const niveaux = /\.(gouv|asso)\.fr$|\.co\.uk$/.test(hote) ? 3 : 2;      // certains suffixes comptent deux niveaux
  return hote.split(".").slice(-niveaux).join(".");
}
for (const u of [
  "https://www.impots.gouv.fr/accueil",
  "https://impots.gouv.fr.remboursement-en-ligne.net/connexion",
  "https://ameli.fr@serveur-inconnu.example/login",
  "http://paypa1.com/securite",
]) console.log(domaine(u).padEnd(28), "←", u);
```

Le cadenas (HTTPS) prouve seulement que la connexion est chiffrée : un site d'hameçonnage peut parfaitement l'afficher.

## 4. Les bons réflexes

- Ne **jamais** cliquer sur le lien d'un message inattendu : aller sur le site en tapant l'adresse soi-même ou via ses favoris.
- Vérifier par un **autre canal** : rappeler la personne sur un numéro connu.
- Ne jamais donner un mot de passe ou un code reçu par SMS : aucun service légitime ne le demande.
- **Signaler** : au service informatique, sur `signal-spam.fr`, par SMS au 33700, sur la plateforme PHAROS.
- Si tu as cliqué et saisi ton mot de passe : le changer **immédiatement** (et partout où il sert), prévenir, surveiller ses comptes.

## 5. Protéger ses comptes

| Mesure | Pourquoi |
| Un **gestionnaire de mots de passe** | un mot de passe long, aléatoire et différent par site, sans avoir à les retenir |
| L'**authentification multifacteur** | un mot de passe volé ne suffit plus |
| Des mises à jour automatiques | les failles connues sont fermées |
| Vérifier ses fuites sur `haveibeenpwned.com` | savoir quels comptes changer |
| Limiter ce qu'on publie | date de naissance, employeur, animaux : tout sert à personnaliser une attaque |

Les facteurs d'authentification : ce que je **sais** (mot de passe), ce que je **possède** (téléphone, clé de sécurité), ce que je **suis** (empreinte). Le MFA en combine au moins deux. Une clé de sécurité matérielle (FIDO2) résiste même à l'hameçonnage ; un code reçu par SMS est le facteur le plus faible.

## 6. Côté entreprise

- **Sensibiliser** régulièrement, avec des campagnes d'hameçonnage simulées (annoncées dans la charte).
- Une procédure pour les virements : **double validation**, rappel sur un numéro connu.
- Filtrage du courrier : anti-spam, analyse des pièces jointes, protocoles **SPF**, **DKIM** et **DMARC** qui empêchent d'usurper le domaine de l'entreprise.
- Un moyen simple de signaler, et **aucune sanction** pour celui qui signale son erreur : la rapidité compte plus que tout.

!tuto Analyser un courriel suspect
# Le message

=== cyber-protections | Cybersécurité : les types de protection | m
Aucune protection n'est parfaite. On en empile donc plusieurs, de nature différente : si l'une cède, la suivante tient. C'est la **défense en profondeur**, comme les enceintes successives d'un château fort.

## 1. Prévenir, détecter, réagir

| Famille | Rôle | Exemples |
| **Prévention** | empêcher l'attaque | pare-feu, mises à jour, MFA, chiffrement, durcissement |
| **Détection** | s'apercevoir qu'elle a lieu | journaux, IDS, antivirus / EDR, supervision, SIEM |
| **Réaction** | limiter les dégâts et repartir | sauvegardes, plan de reprise, procédure d'incident |

Une entreprise qui ne fait que de la prévention découvre son intrusion des mois plus tard.

## 2. Filtrer le réseau

| Protection | Rôle |
| **Pare-feu** | autorise ou bloque les flux selon des règles (adresse, port, protocole) |
| **DMZ** | zone isolée pour les serveurs exposés à Internet (web, messagerie) |
| **Segmentation** (VLAN) | séparer les réseaux : élèves, administration, serveurs, invités |
| **VPN** | tunnel chiffré pour les accès distants |
| **Proxy** / filtrage web | bloque les sites dangereux, journalise |
| **WAF** | pare-feu applicatif : filtre les requêtes HTTP malveillantes |
| **IDS / IPS** | détecte (IDS) ou bloque (IPS) les comportements suspects sur le réseau |
| **NAC / 802.1X** | n'accepte sur le réseau que les machines authentifiées |

La règle d'or d'un pare-feu : **tout interdire par défaut**, puis autoriser seulement ce qui est nécessaire.

```
# Exemple avec ufw sur un serveur web Linux
sudo ufw default deny incoming       # tout ce qui entre est refusé par défaut
sudo ufw default allow outgoing
sudo ufw allow 443/tcp               # HTTPS pour tout le monde
sudo ufw allow from 192.168.10.0/24 to any port 22 proto tcp   # SSH : réseau d'administration seulement
sudo ufw enable
sudo ufw status verbose
```

## 3. Protéger les postes et les serveurs

| Protection | Rôle |
| **Mises à jour** (gestion des correctifs) | ferme les failles connues : la mesure la plus rentable |
| **Antivirus** | reconnaît les malwares connus par leur signature |
| **EDR** | surveille les **comportements** (un tableur qui lance PowerShell) et peut isoler le poste |
| **Durcissement** (*hardening*) | désactiver l'inutile, configurer strictement |
| **Chiffrement du disque** (BitLocker, LUKS) | un portable volé ne livre pas ses données |
| **Liste blanche d'applications** | seuls les programmes approuvés s'exécutent |
| **Comptes sans droits administrateur** | un malware lancé par l'utilisateur ne peut pas tout casser |

## 4. Contrôler les accès

- **Moindre privilège** : chaque compte n'a que les droits nécessaires à son travail.
- **Séparation des tâches** : celui qui demande n'est pas celui qui valide.
- **MFA** sur tout ce qui est exposé : messagerie, VPN, administration.
- Des comptes **nominatifs** (pas de compte « admin » partagé), désactivés dès le départ de la personne.
- Un **bastion** : point de passage unique et journalisé pour administrer les serveurs.
- Modèle **Zero Trust** : ne jamais faire confiance par défaut, même à l'intérieur du réseau ; vérifier chaque accès.

## 5. Protéger les données

| Mesure | Protège |
| Chiffrement **en transit** (TLS, VPN) | contre l'écoute du réseau |
| Chiffrement **au repos** (disque, base de données) | contre le vol du support |
| **Sauvegardes 3-2-1** | 3 copies, 2 supports, 1 hors site, dont une **hors ligne** que le rançongiciel ne peut pas atteindre |
| Tests de restauration | une sauvegarde jamais testée n'est qu'un espoir |
| Classification et droits | qui a le droit de lire quoi |
| Effacement sécurisé | avant de donner ou de jeter un disque |

## 6. Surveiller

| Outil | Rôle |
| Journaux (*logs*) centralisés | garder la trace de ce qui se passe, hors de portée de l'attaquant |
| **SIEM** | rassemble et corrèle les journaux, déclenche des alertes |
| **SOC** | l'équipe qui surveille les alertes, souvent 24 h sur 24 |
| Supervision (Zabbix, Nagios) | disponibilité et charge des services |
| Scanner de vulnérabilités | liste les failles connues de son propre parc |
| *Honeypot* (pot de miel) | un leurre : toute connexion y est suspecte |

## 7. L'organisation

La technique ne suffit pas : il faut une **politique de sécurité** (PSSI), une **charte** signée par les utilisateurs, de la **sensibilisation**, un **plan de continuité** (PCA : continuer pendant la crise) et un **plan de reprise** (PRA : redémarrer après), avec deux objectifs chiffrés : le **RTO** (durée maximale d'interruption) et le **RPO** (quantité maximale de données perdues, donc fréquence des sauvegardes). Le guide d'hygiène informatique de l'ANSSI résume 42 mesures de base.

!tuto Sécuriser le réseau d'une petite entreprise
# L'état des lieux
Une box, un seul réseau pour tout le monde, un NAS avec le mot de passe d'usine, pas de sauvegarde externe, le même compte « admin » pour les cinq employés.
# Les mesures immédiates, gratuites
Changer tous les mots de passe par défaut ; un compte nominatif par personne ; activer les mises à jour automatiques ; activer le MFA sur la messagerie ; désactiver l'accès distant inutile de la box.
# Les mesures structurantes
Séparer le réseau en trois : postes, serveurs, invités (Wi-Fi séparé). Un pare-feu qui interdit par défaut. Sauvegarde quotidienne du NAS vers un disque déconnecté et vers un stockage distant chiffré.
# Vérifier
Restaurer un fichier depuis la sauvegarde. Regarder les journaux du pare-feu. Recommencer chaque mois.
!fin

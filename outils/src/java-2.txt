=== java-poo | Java : programmation orientée objet | d
Java est un langage **orienté objet** : un programme est un ensemble d'**objets** qui collaborent. Une **classe** est le plan de fabrication ; un **objet** (ou *instance*) est un exemplaire construit à partir de ce plan.

## 1. Une première classe

```run cls main
class Joueur {
    String nom;                 // attributs : les données de chaque objet
    int pv;

    void blesser(int degats) {  // méthode : agit sur l'objet
        pv = pv - degats;
    }
}
@@
Joueur a = new Joueur();        // new crée un objet
a.nom = "Léa";
a.pv = 10;
Joueur b = new Joueur();
b.nom = "Sam";
b.pv = 5;
a.blesser(3);
System.out.println(a.nom + " : " + a.pv + ", " + b.nom + " : " + b.pv);
```

Chaque objet a **ses propres** valeurs d'attributs. Remarque que `blesser` n'est pas `static` : elle s'applique à **un** objet.

## 2. Le constructeur et `this`

Le **constructeur** porte le nom de la classe, n'a pas de type de retour, et s'exécute au moment du `new`. `this` désigne l'objet en cours.

```run cls main
class Joueur {
    String nom;
    int pv;

    Joueur(String nom, int pv) {     // constructeur
        this.nom = nom;              // this.nom = l'attribut ; nom = le paramètre
        this.pv = pv;
    }
    Joueur(String nom) {             // surcharge : un second constructeur
        this(nom, 10);               // appelle le premier
    }
}
@@
Joueur a = new Joueur("Léa", 20);
Joueur b = new Joueur("Sam");
System.out.println(a.nom + " " + a.pv + ", " + b.nom + " " + b.pv);
```

## 3. L'encapsulation : `private`, accesseurs

On interdit l'accès direct aux attributs (`private`) et on n'expose que des méthodes qui gardent l'objet dans un état cohérent.

```run cls main
class Compte {
    private String titulaire;
    private double solde;

    public Compte(String titulaire, double solde) {
        this.titulaire = titulaire;
        this.solde = solde;
    }

    public void deposer(double montant) {
        if (montant > 0) solde += montant;
    }
    public boolean retirer(double montant) {
        if (montant > solde) return false;
        solde -= montant;
        return true;
    }
    public double getSolde() { return solde; }               // accesseur (getter)
    public String getTitulaire() { return titulaire; }
    public void setTitulaire(String t) {                      // mutateur (setter), avec contrôle
        if (t != null && !t.isBlank()) titulaire = t;
    }
}
@@
Compte c = new Compte("Léa", 100);
c.deposer(50);
System.out.println(c.retirer(500) + " " + c.retirer(30) + " " + c.getSolde());
// c.solde = 1000000;     // refusé à la compilation : solde est private
```

| `private` | la classe uniquement |
| (rien) | les classes du même paquetage |
| `protected` | le paquetage et les classes filles |
| `public` | partout |

## 4. `toString` et `equals`

`println(objet)` appelle sa méthode `toString()`. Par défaut elle affiche quelque chose comme `Point@1b6d3586` : on la **redéfinit**. De même, `equals` par défaut ne compare que les références.

```run cls main
class Point {
    private final int x, y;          // final : fixés par le constructeur, jamais modifiés

    Point(int x, int y) { this.x = x; this.y = y; }

    @Override
    public String toString() { return "(" + x + ", " + y + ")"; }

    @Override
    public boolean equals(Object autre) {
        if (!(autre instanceof Point)) return false;
        Point p = (Point) autre;
        return x == p.x && y == p.y;
    }
    @Override
    public int hashCode() { return 31 * x + y; }     // toujours redéfini avec equals
}
@@
Point a = new Point(3, 4), b = new Point(3, 4);
System.out.println(a);                    // appelle toString
System.out.println(a == b);               // false : deux objets distincts
System.out.println(a.equals(b));          // true  : même contenu
```

## 5. `static` : ce qui appartient à la classe

Un membre `static` est **partagé** par tous les objets et s'utilise avec le nom de la classe.

```run cls main
class Ticket {
    private static int prochain = 1;          // un seul compteur pour toute la classe
    public static final int MAX = 999;        // constante de classe
    private final int numero;

    Ticket() { numero = prochain++; }
    int getNumero() { return numero; }
    static int dejaEmis() { return prochain - 1; }      // méthode de classe : pas de this
}
@@
Ticket a = new Ticket(), b = new Ticket(), c = new Ticket();
System.out.println(a.getNumero() + " " + c.getNumero() + " " + Ticket.dejaEmis() + " " + Ticket.MAX);
```

C'est pour cela que `main` est `static` : elle est appelée avant qu'un seul objet n'existe. `Math.sqrt`, `Integer.parseInt` sont aussi des méthodes de classe.

## 6. Les références et `null`

Une variable d'objet contient une **référence** vers l'objet, pas l'objet lui-même.

```run cls main
class Boite {
    int valeur;
    Boite(int v) { valeur = v; }
}
@@
Boite a = new Boite(1);
Boite b = a;                 // b désigne LE MÊME objet
b.valeur = 99;
System.out.println(a.valeur);          // 99
Boite c = null;              // ne désigne aucun objet
if (c == null) System.out.println("c est vide");
// c.valeur = 5;             // NullPointerException : l'erreur la plus fréquente en Java
```

La mémoire des objets devenus inaccessibles est récupérée automatiquement par le **ramasse-miettes** (*garbage collector*) : pas de `delete` en Java.

## 7. Des objets qui contiennent des objets

```run imp=java.util.ArrayList cls main
class Eleve {
    private final String nom;
    private final double note;
    Eleve(String nom, double note) { this.nom = nom; this.note = note; }
    String getNom() { return nom; }
    double getNote() { return note; }
}

class Classe {
    private final ArrayList<Eleve> eleves = new ArrayList<>();
    void ajouter(Eleve e) { eleves.add(e); }
    double moyenne() {
        double somme = 0;
        for (Eleve e : eleves) somme += e.getNote();
        return eleves.isEmpty() ? 0 : somme / eleves.size();
    }
    Eleve meilleur() {
        Eleve m = eleves.get(0);
        for (Eleve e : eleves) if (e.getNote() > m.getNote()) m = e;
        return m;
    }
}
@@
Classe sio = new Classe();
sio.ajouter(new Eleve("Léa", 15));
sio.ajouter(new Eleve("Sam", 9));
sio.ajouter(new Eleve("Zoé", 18));
System.out.println(sio.moyenne() + " " + sio.meilleur().getNom());
```

Une Classe **a des** élèves : c'est la **composition**, à ne pas confondre avec l'héritage (« est un »).

=== java-heritage | Java : héritage, classes abstraites et interfaces | d
## 1. Hériter avec `extends`

Une classe **fille** reprend les attributs et les méthodes de sa classe **mère** et peut en ajouter ou en redéfinir. En Java, une classe n'a qu'**une seule** classe mère.

```run cls main
class Personnage {
    protected String nom;            // protected : visible des classes filles
    protected int pv;

    Personnage(String nom, int pv) { this.nom = nom; this.pv = pv; }
    void blesser(int d) { pv = Math.max(0, pv - d); }
    @Override
    public String toString() { return nom + " : " + pv + " PV"; }
}

class Guerrier extends Personnage {          // Guerrier EST UN Personnage
    private final int force;

    Guerrier(String nom, int force) {
        super(nom, 20);                      // appelle le constructeur de la mère (1re ligne)
        this.force = force;
    }
    void frapper(Personnage cible) { cible.blesser(force); }
}
@@
Guerrier g = new Guerrier("Conan", 7);
Personnage p = new Personnage("Gobelin", 10);
g.frapper(p);
System.out.println(g);          // toString hérité
System.out.println(p);
```

## 2. Redéfinir une méthode : `@Override` et `super`

```run cls main
class Employe {
    protected String nom;
    protected double salaire;
    Employe(String nom, double salaire) { this.nom = nom; this.salaire = salaire; }
    double paie() { return salaire; }
    String fiche() { return nom + " : " + paie() + " €"; }
}

class Commercial extends Employe {
    private final double ventes;
    Commercial(String nom, double salaire, double ventes) {
        super(nom, salaire);
        this.ventes = ventes;
    }
    @Override
    double paie() { return super.paie() + ventes * 0.05; }     // la paie de base + une commission
}
@@
Employe e = new Employe("Léa", 2000);
Employe c = new Commercial("Sam", 2000, 10000);       // un Commercial rangé dans une variable Employe
System.out.println(e.fiche());
System.out.println(c.fiche());                        // fiche() appelle le paie() du Commercial
```

`@Override` demande au compilateur de vérifier qu'on redéfinit bien une méthode existante : une faute de frappe dans le nom devient une erreur de compilation au lieu d'un bug silencieux.

## 3. Le polymorphisme

Une variable de type `Employe` peut désigner n'importe quel objet d'une classe fille. La méthode exécutée est celle de la **classe réelle** de l'objet, décidée à l'exécution. En Java, c'est le comportement par défaut (pas de mot-clé `virtual`).

```run imp=java.util.List cls main
class Animal {
    protected final String nom;
    Animal(String nom) { this.nom = nom; }
    String crier() { return "..."; }
    String presenter() { return nom + " fait " + crier(); }
}
class Chien extends Animal {
    Chien(String nom) { super(nom); }
    @Override String crier() { return "Ouaf"; }
}
class Chat extends Animal {
    Chat(String nom) { super(nom); }
    @Override String crier() { return "Miaou"; }
}
@@
List<Animal> animaux = List.of(new Chien("Rex"), new Chat("Tigrou"), new Animal("Truc"));
for (Animal a : animaux) {
    System.out.println(a.presenter());
}
Animal x = animaux.get(0);
if (x instanceof Chien c) System.out.println(c.nom + " est un chien");     // test du type réel
```

## 4. Les classes abstraites

Une classe `abstract` ne peut pas être instanciée. Elle peut déclarer des **méthodes abstraites** (sans corps) que chaque classe fille **doit** définir.

```run imp=java.util.List cls main
abstract class Forme {
    abstract double aire();                              // pas de corps
    abstract String nom();
    String description() { return nom() + " d'aire " + aire(); }     // méthode normale, commune
}
class Rectangle extends Forme {
    private final double l, h;
    Rectangle(double l, double h) { this.l = l; this.h = h; }
    @Override double aire() { return l * h; }
    @Override String nom() { return "rectangle"; }
}
class Cercle extends Forme {
    private final double r;
    Cercle(double r) { this.r = r; }
    @Override double aire() { return Math.PI * r * r; }
    @Override String nom() { return "cercle"; }
}
@@
List<Forme> formes = List.of(new Rectangle(3, 4), new Cercle(1));
double total = 0;
for (Forme f : formes) {
    System.out.println(f.description());
    total += f.aire();
}
System.out.printf("Aire totale : %.2f%n", total);
// Forme f = new Forme();     // refusé : classe abstraite
```

## 5. Les interfaces

Une **interface** est un contrat : une liste de méthodes qu'une classe s'engage à fournir. Une classe n'hérite que d'une classe, mais peut **implémenter plusieurs interfaces**.

```run imp=java.util.List cls main
interface Affichable {
    String afficher();
}
interface Exportable {
    String versCsv();
    default String entete() { return "nom;valeur"; }      // méthode par défaut (Java 8+)
}

class Produit implements Affichable, Exportable {
    private final String nom;
    private final double prix;
    Produit(String nom, double prix) { this.nom = nom; this.prix = prix; }
    @Override public String afficher() { return nom + " (" + prix + " €)"; }
    @Override public String versCsv() { return nom + ";" + prix; }
}
class Client implements Exportable {
    private final String nom;
    Client(String nom) { this.nom = nom; }
    @Override public String versCsv() { return nom + ";client"; }
}
@@
Produit p = new Produit("Souris", 19.9);
System.out.println(p.afficher());
List<Exportable> aExporter = List.of(p, new Client("Léa"));      // des classes sans lien entre elles
System.out.println(aExporter.get(0).entete());
for (Exportable e : aExporter) System.out.println(e.versCsv());
```

| | Classe abstraite | Interface |
| Attributs d'instance | oui | non (seulement des constantes) |
| Constructeur | oui | non |
| Combien par classe | une seule (`extends`) | plusieurs (`implements`) |
| Sert à | partager du **code** entre classes proches | définir une **capacité** commune |

Les interfaces sont partout dans Java : `List` est une interface, `ArrayList` une classe qui l'implémente ; `Comparable`, `Runnable`, `Iterable` aussi.

## 6. `final` et la classe `Object`

Une méthode `final` ne peut pas être redéfinie ; une classe `final` ne peut pas avoir de fille (c'est le cas de `String`). Enfin, toute classe hérite implicitement de `Object`, d'où viennent `toString`, `equals` et `hashCode`.

!attention Héritage ou composition ? | N'utilise l'héritage que pour une vraie relation « est un ». Si tu veux seulement réutiliser du code (« a un »), mets un attribut : une Voiture **a un** Moteur, elle n'hérite pas de Moteur.

# Les traiter toutes de la même façon
La classe `Alerte` ne connaît que l'interface. Ajoute un canal `Slack` : la classe `Alerte` ne change pas d'une ligne.
```run imp=java.util.ArrayList,java.util.List cls main
interface Notification {
    void envoyer(String message);
}
class Email implements Notification {
    @Override public void envoyer(String message) { System.out.println("[mail] " + message); }
}
class Sms implements Notification {
    @Override public void envoyer(String message) { System.out.println("[sms] " + message); }
}
class Alerte {
    private final List<Notification> canaux = new ArrayList<>();
    void abonner(Notification n) { canaux.add(n); }
    void declencher(String message) {
        for (Notification n : canaux) n.envoyer(message);
    }
}
@@
Alerte a = new Alerte();
a.abonner(new Email());
a.abonner(new Sms());
a.declencher("Disque plein");
```

=== java-collections | Java : les collections et les génériques | m
Les **collections** (paquetage `java.util`) sont les structures de données prêtes à l'emploi de Java. Trois suffisent pour presque tout : la **liste**, le **dictionnaire**, l'**ensemble**.

## 1. `ArrayList` : la liste qui grandit

```run imp=java.util.ArrayList,java.util.List main
List<String> fruits = new ArrayList<>();        // <String> : le type des éléments
fruits.add("pomme");
fruits.add("kiwi");
fruits.add(0, "ananas");                        // insère à l'indice 0
System.out.println(fruits + " " + fruits.size());
System.out.println(fruits.get(1));              // lecture par indice
fruits.set(1, "poire");                         // remplacement
fruits.remove("kiwi");                          // suppression par valeur
fruits.remove(0);                               // suppression par indice
System.out.println(fruits + " " + fruits.contains("poire") + " " + fruits.indexOf("poire") + " " + fruits.isEmpty());

for (String f : fruits) System.out.println(f.toUpperCase());
```

`List` est l'**interface**, `ArrayList` la classe concrète. On déclare la variable avec l'interface : le reste du code ne dépend pas de l'implémentation choisie.

## 2. Les génériques et les types enveloppes

Le type entre chevrons est un **paramètre de type**. Il doit être une classe : pour les types primitifs, on utilise leur **enveloppe** (`Integer`, `Double`, `Boolean`, `Character`). La conversion est automatique (*autoboxing*).

```run imp=java.util.ArrayList,java.util.List,java.util.Collections main
List<Integer> notes = new ArrayList<>(List.of(12, 5, 19, 8));     // List.of : liste non modifiable
notes.add(10);                               // int → Integer automatiquement
int somme = 0;
for (int n : notes) somme += n;              // Integer → int automatiquement
System.out.println(somme + " " + Collections.max(notes) + " " + Collections.min(notes));
Collections.sort(notes);
System.out.println(notes);
Collections.reverse(notes);
System.out.println(notes);
// List<int> x;        // refusé : pas de type primitif entre chevrons
```

Grâce aux génériques, le compilateur refuse `notes.add("texte")` : les erreurs de type sont détectées avant l'exécution.

## 3. `HashMap` : le dictionnaire

```run imp=java.util.HashMap,java.util.Map,java.util.TreeMap main
Map<String, Integer> stock = new HashMap<>();
stock.put("souris", 3);
stock.put("clavier", 2);
stock.put("souris", 8);                                   // même clé : la valeur est remplacée
System.out.println(stock.get("souris") + " " + stock.get("webcam"));       // 8 null
System.out.println(stock.getOrDefault("webcam", 0) + " " + stock.containsKey("clavier") + " " + stock.size());

stock.put("ecran", stock.getOrDefault("ecran", 0) + 1);   // compter
stock.merge("ecran", 1, Integer::sum);                    // la même chose, en plus court

for (Map.Entry<String, Integer> e : stock.entrySet()) {   // parcourir clés et valeurs
    System.out.println(e.getKey() + " : " + e.getValue());
}
System.out.println(new TreeMap<>(stock));                 // TreeMap : clés triées
stock.remove("clavier");
System.out.println(stock.keySet() + " " + stock.values());
```

!attention L'ordre d'une `HashMap` | Une `HashMap` ne garantit **aucun** ordre de parcours. Pour des clés triées, utilise `TreeMap` ; pour garder l'ordre d'insertion, `LinkedHashMap`.

## 4. `HashSet` : l'ensemble sans doublon

```run imp=java.util.HashSet,java.util.Set,java.util.TreeSet,java.util.List main
Set<String> vus = new HashSet<>();
System.out.println(vus.add("lua") + " " + vus.add("java") + " " + vus.add("lua"));    // add renvoie false si déjà présent
System.out.println(vus.size() + " " + vus.contains("java"));
Set<Integer> uniques = new TreeSet<>(List.of(5, 2, 5, 8, 2));      // TreeSet : trié
System.out.println(uniques);
```

| suite ordonnée, accès par indice | `List` | `ArrayList` |
| clé → valeur | `Map` | `HashMap` (ou `TreeMap` triée) |
| valeurs uniques | `Set` | `HashSet` (ou `TreeSet` trié) |
| pile, file | `Deque` | `ArrayDeque` |

## 5. Trier des objets : `Comparator`

```run imp=java.util.ArrayList,java.util.List,java.util.Comparator cls main

    final String nom;
    final double note;
    Eleve(String nom, double note) { this.nom = nom; this.note = note; }
    @Override public String toString() { return nom + " " + note; }
}
@@

classe.add(new Eleve("Sam", 9));
classe.add(new Eleve("Zoé", 18));
```

Un `Comparator` renvoie un nombre négatif, nul ou positif selon que le premier élément passe avant, est égal, ou passe après le second.

## 6. Supprimer pendant un parcours

Modifier une liste dans un `for-each` lève une `ConcurrentModificationException`. La bonne méthode : `removeIf`.

```run imp=java.util.ArrayList,java.util.List main

tirs.removeIf(y -> y < 0);                  // supprime selon une condition
System.out.println(tirs);
```

=== java-exceptions | Java : les exceptions | m
Une **exception** est un objet qui signale une erreur survenue pendant l'exécution. Si personne ne l'attrape, le programme s'arrête en affichant la pile d'appels (*stack trace*). Savoir la lire et la gérer distingue un exercice d'un programme fiable.

## 1. Attraper : `try` / `catch`

```run main
String[] saisies = {"42", "abc", "7"};
for (String s : saisies) {
    try {
        int n = Integer.parseInt(s);            // peut lever NumberFormatException
        System.out.println(n + " x 2 = " + n * 2);
    } catch (NumberFormatException e) {
        System.out.println("« " + s + " » n'est pas un nombre");
    }
}
System.out.println("le programme continue");
```

Dès qu'une exception est levée dans le `try`, le reste du bloc est **sauté** et l'exécution reprend dans le `catch` correspondant.

## 2. Plusieurs `catch`, et `finally`

```run main
static int diviser(String a, String b) {
    return Integer.parseInt(a) / Integer.parseInt(b);
}
@@
String[][] essais = {{"10", "2"}, {"10", "0"}, {"dix", "2"}};
for (String[] e : essais) {
    try {
        System.out.println(diviser(e[0], e[1]));
    } catch (ArithmeticException ex) {
        System.out.println("Calcul impossible : " + ex.getMessage());
    } catch (NumberFormatException ex) {
        System.out.println("Saisie invalide : " + ex.getMessage());
    } finally {
        System.out.println("  (essai terminé)");        // exécuté dans TOUS les cas
    }
}
```

`finally` sert à libérer une ressource (fermer un fichier, une connexion) qu'il y ait eu une erreur ou non. On peut regrouper deux types : `catch (ArithmeticException | NumberFormatException ex)`.

## 3. Les exceptions courantes

| Exception | Cause |
| `NullPointerException` | appel d'une méthode sur `null` |
| `ArrayIndexOutOfBoundsException` | indice de tableau invalide |
| `IndexOutOfBoundsException` | indice de liste invalide |
| `NumberFormatException` | texte non convertible en nombre |
| `ArithmeticException` | division entière par zéro |
| `ClassCastException` | conversion de type impossible |
| `IllegalArgumentException` | argument refusé par une méthode |
| `IOException` | problème de fichier ou de réseau |

!info Dans le navigateur | Sur ce site, le Java est traduit en WebAssembly : quelques erreurs très bas niveau (méthode appelée sur `null`, indice de tableau invalide) arrêtent directement le programme au lieu de lever une exception attrapable. Avec une vraie JVM, toutes s'attrapent.

## 4. Lever une exception : `throw`

```run cls main
class Compte {
    private double solde;
    Compte(double solde) {
        if (solde < 0) throw new IllegalArgumentException("solde initial négatif");
        this.solde = solde;
    }
    void retirer(double montant) {
        if (montant <= 0) throw new IllegalArgumentException("montant invalide : " + montant);
        if (montant > solde) throw new IllegalStateException("solde insuffisant");
        solde -= montant;
    }
    double getSolde() { return solde; }
}
@@
Compte c = new Compte(100);
try {
    c.retirer(30);
    c.retirer(500);                  // lève : la ligne suivante est sautée
    c.retirer(10);
} catch (IllegalStateException | IllegalArgumentException e) {
    System.out.println("Refusé : " + e.getMessage());
}
System.out.println(c.getSolde());
```

Une méthode qui ne peut pas faire son travail ne doit ni renvoyer une valeur bidon ni afficher un message : elle **lève une exception**, et c'est l'appelant qui décide quoi faire.

## 5. Créer sa propre exception

```run cls main

    private final double manque;
    SoldeInsuffisantException(double manque) {
        super("il manque " + manque + " €");
        this.manque = manque;
    }
    double getManque() { return manque; }
}

class Compte {
    private double solde = 100;
    void retirer(double montant) throws SoldeInsuffisantException {      // throws : annonce le risque
        if (montant > solde) throw new SoldeInsuffisantException(montant - solde);
        solde -= montant;
    }
}
@@
Compte c = new Compte();
try {
    c.retirer(250);
} catch (SoldeInsuffisantException e) {
    System.out.println(e.getMessage() + " (" + e.getManque() + ")");
}
```

## 6. Exceptions vérifiées et non vérifiées

| | Vérifiées (*checked*) | Non vérifiées (*unchecked*) |
| Héritent de | `Exception` | `RuntimeException` |
| Le compilateur impose | `try/catch` ou `throws` | rien |
| Représentent | un problème extérieur prévisible (fichier absent, réseau) | un bug du programme (indice, null, argument) |
| Exemples | `IOException`, `SQLException` | `NullPointerException`, `IllegalArgumentException` |

Une exception non attrapée **remonte** d'appel en appel. Une méthode qui laisse passer une exception vérifiée doit le déclarer avec `throws` :

```run main
static int lireAge(String texte) {                    // NumberFormatException est non vérifiée : pas de throws
    int age = Integer.parseInt(texte.trim());
    if (age < 0 || age > 130) throw new IllegalArgumentException("âge impossible : " + age);
    return age;
}
@@
for (String s : new String[]{" 17 ", "abc", "250"}) {
    try {
        System.out.println("âge valide : " + lireAge(s));
    } catch (NumberFormatException e) {                // plus spécifique d'abord
        System.out.println("pas un nombre : " + s);
    } catch (IllegalArgumentException e) {
        System.out.println(e.getMessage());
    }
}
```

!attention L'ordre des `catch` | `NumberFormatException` hérite d'`IllegalArgumentException` : le `catch` le plus **spécifique** doit être écrit en premier, sinon il est inatteignable et le compilateur refuse.

## 7. `try`-with-resources

Pour les ressources à fermer (fichiers, connexions à une base de données), cette forme appelle `close()` automatiquement, même en cas d'erreur :

```
try (BufferedReader lecteur = new BufferedReader(new FileReader("notes.txt"))) {
    String ligne;
    while ((ligne = lecteur.readLine()) != null) {
        System.out.println(ligne);
    }
} catch (IOException e) {
    System.out.println("Lecture impossible : " + e.getMessage());
}
```

!attention Ne jamais avaler une exception | Un `catch (Exception e) { }` vide fait disparaître l'erreur : le programme continue avec des données fausses et le bug devient introuvable. Au minimum, affiche ou journalise le message, et n'attrape que les exceptions que tu sais traiter.

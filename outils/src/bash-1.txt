=== bash-scripts | Bash : écrire son premier script | f
Un **script Bash** est un fichier texte qui contient les commandes que tu taperais dans le terminal. L'administrateur système s'en sert pour **automatiser** tout ce qui se répète : sauvegardes, création de comptes, installation de serveurs, surveillance. Ce cours prolonge les chapitres Linux de la matière SISR.

## 1. Le premier script

```
#!/bin/bash
# sauvegarde.sh : mon premier script
echo "Bonjour $USER"
echo "Nous sommes le $(date +%d/%m/%Y)"
```

```
chmod +x sauvegarde.sh       # donne le droit d'exécution
./sauvegarde.sh              # lance le script
bash sauvegarde.sh           # autre façon, sans le droit x
```

La première ligne `#!/bin/bash` (le *shebang*) indique quel programme doit interpréter le fichier.

## 2. Les variables

```
nom="Léa"                    # PAS d'espace autour du =
age=17
echo "Bonjour $nom, tu as $age ans"
echo "Fichier : ${nom}_notes.txt"        # accolades pour délimiter le nom
readonly MAX=10                          # constante
```

!attention Pas d'espace autour du `=` | `nom = "Léa"` ne fonctionne pas : Bash cherche une commande appelée `nom`. C'est l'erreur numéro 1 en Bash.

## 3. Guillemets : doubles, simples, ou rien

| Écriture | Effet | `echo` affiche (avec `nom=Léa`) |
| `"Bonjour $nom"` | les variables sont remplacées | `Bonjour Léa` |
| `'Bonjour $nom'` | texte littéral, rien n'est remplacé | `Bonjour $nom` |
| `$nom` sans guillemets | remplacé, puis **découpé** sur les espaces | dangereux |

Règle : mets **toujours** tes variables entre guillemets doubles : `rm "$fichier"`. Sans eux, un nom de fichier contenant un espace est coupé en deux.

## 4. Substitution de commande et calculs

```
aujourdhui=$(date +%F)                   # le résultat d'une commande dans une variable
nb=$(ls /etc | wc -l)
echo "Il y a $nb fichiers dans /etc"

total=$(( 5 + 3 * 2 ))                   # calcul entier : $(( … ))
compteur=$(( compteur + 1 ))
echo "$(( 17 / 5 )) reste $(( 17 % 5 ))"
```

## 5. Les arguments du script

```
#!/bin/bash
echo "Nom du script : $0"
echo "Premier argument : $1"
echo "Deuxième argument : $2"
echo "Nombre d'arguments : $#"
echo "Tous les arguments : $@"
```

```
./creer.sh lea sio1          # $1 vaut lea, $2 vaut sio1, $# vaut 2
```

## 6. Lire une saisie

```
read -p "Nom d'utilisateur : " utilisateur
read -s -p "Mot de passe : " motdepasse      # -s : saisie masquée
echo
echo "Création de $utilisateur…"
```

## 7. Le code de retour

Chaque commande renvoie un **code de retour** : `0` signifie succès, toute autre valeur une erreur. Il est disponible dans `$?` juste après la commande.

```
ls /etc/passwd
echo $?                      # 0 : succès
ls /dossier/inexistant
echo $?                      # 2 : erreur
exit 1                       # un script signale lui-même son échec
```

| Enchaînement | Signifie |
| `cmd1 && cmd2` | cmd2 seulement si cmd1 a réussi |
| `cmd1 || cmd2` | cmd2 seulement si cmd1 a échoué |
| `cmd1 ; cmd2` | cmd2 dans tous les cas |

```
mkdir /sauvegardes && echo "Dossier créé" || echo "Échec de la création"
```


=== bash-conditions-boucles | Bash : conditions, boucles et fonctions | m
## 1. `if` et les tests

```
if [[ -f /etc/passwd ]]; then
    echo "Le fichier existe"
elif [[ -d /etc ]]; then
    echo "Seul le dossier existe"
else
    echo "Rien"
fi
```

Les espaces après `[[` et avant `]]` sont **obligatoires**. `fi` ferme le `if`.

| Test sur les fichiers | Vrai si |
| `-e chemin` | le chemin existe |
| `-f chemin` | c'est un fichier |
| `-d chemin` | c'est un dossier |
| `-r` `-w` `-x` | lisible, modifiable, exécutable |
| `-s chemin` | le fichier n'est pas vide |

| Test sur les textes | Vrai si |
| `"$a" == "$b"` | égaux |
| `"$a" != "$b"` | différents |
| `-z "$a"` | vide |
| `-n "$a"` | non vide |

| Test sur les nombres | Vrai si |
| `-eq` `-ne` | égal, différent |
| `-lt` `-le` | inférieur, inférieur ou égal |
| `-gt` `-ge` | supérieur, supérieur ou égal |

```
if [[ $# -lt 1 ]]; then
    echo "Usage : $0 <utilisateur>" >&2      # >&2 : sur la sortie d'erreur
    exit 1
fi

if [[ "$USER" != "root" ]]; then
    echo "Ce script doit être lancé avec sudo" >&2
    exit 1
fi

if (( age >= 18 )); then echo "majeur"; fi   # (( )) : comparaisons arithmétiques classiques
if [[ -d "$dossier" && -w "$dossier" ]]; then echo "dossier modifiable"; fi
```

Un `if` peut aussi tester directement le **succès d'une commande** :

```
if grep -q "^lea:" /etc/passwd; then
    echo "L'utilisateur lea existe"
fi
if ! ping -c 1 -W 2 192.168.1.1 > /dev/null; then
    echo "La passerelle ne répond pas"
fi
```

## 2. `case`

```
case "$1" in
    start)   echo "Démarrage" ;;
    stop)    echo "Arrêt" ;;
    restart) echo "Redémarrage" ;;
    *)       echo "Usage : $0 {start|stop|restart}" ; exit 1 ;;
esac
```

## 3. La boucle `for`

```
for prenom in lea sam zoe; do
    echo "Bonjour $prenom"
done

for fichier in /var/log/*.log; do            # tous les fichiers correspondants
    echo "$fichier : $(wc -l < "$fichier") lignes"
done

for i in {1..5}; do echo "Tour $i"; done     # une suite de nombres
for (( i = 0; i < 3; i++ )); do echo "$i"; done

for arg in "$@"; do echo "Argument : $arg"; done
```

## 4. La boucle `while`

```
compteur=1
while [[ $compteur -le 3 ]]; do
    echo "Essai $compteur"
    compteur=$(( compteur + 1 ))
done

while read -r ligne; do                      # lire un fichier ligne par ligne
    echo "Lu : $ligne"
done < utilisateurs.txt

while IFS=";" read -r nom prenom classe; do  # découper un fichier CSV
    echo "$prenom $nom est en $classe"
done < eleves.csv
```

`break` sort de la boucle, `continue` passe au tour suivant.

## 5. Les fonctions

```
journal() {
    echo "[$(date '+%F %T')] $1" >> /var/log/monscript.log
}

existe_utilisateur() {
    id "$1" > /dev/null 2>&1                 # le code de retour de id devient celui de la fonction
}

journal "Début du traitement"
if existe_utilisateur "lea"; then
    journal "lea existe déjà"
fi
```

Dans une fonction, `$1`, `$2`… sont **ses** arguments. `local variable=valeur` crée une variable propre à la fonction ; `return n` fixe son code de retour.

## 6. Un script robuste

```
#!/bin/bash
set -euo pipefail
# -e : arrête le script à la première erreur
# -u : erreur si on utilise une variable non définie
# -o pipefail : une erreur dans un tube n'est pas masquée
```

!tuto Créer des comptes à partir d'un fichier
# Vérifier les arguments et les droits
```
#!/bin/bash
set -euo pipefail
if [[ $# -ne 1 || ! -f "$1" ]]; then
    echo "Usage : $0 <fichier.csv>" >&2
    exit 1

    echo "À lancer avec sudo" >&2

```

Chaque ligne contient `identifiant;Nom complet`.
```
while IFS=";" read -r identifiant nom; do

```
# Créer seulement ceux qui n'existent pas
```
while IFS=";" read -r identifiant nom; do
    if id "$identifiant" > /dev/null 2>&1; then
        echo "$identifiant existe déjà : ignoré"
        continue
    fi
    useradd -m -c "$nom" -s /bin/bash "$identifiant"
    echo "$identifiant créé"
done < "$1"
```

=== bash-regex-texte | Bash : expressions régulières, grep, sed et awk | m
Journaux, fichiers de configuration, exports CSV : l'administration système consiste beaucoup à **chercher et transformer du texte**. Les expressions régulières (*regex*) décrivent des motifs de texte ; on les retrouve à l'identique en PHP, JavaScript, Java, Python.

## 1. Les expressions régulières

| Motif | Signifie | Exemple |
| `.` | n'importe quel caractère | `a.c` : abc, a5c |
| `^` `$` | début, fin de ligne | `^root`, `bash$` |
| `[abc]` `[a-z]` `[0-9]` | un caractère de l'ensemble | `[0-9][0-9]` |
| `[^0-9]` | un caractère hors de l'ensemble | |
| `*` | 0 fois ou plus | `ab*` : a, ab, abbb |
| `+` | 1 fois ou plus | `[0-9]+` |
| `?` | 0 ou 1 fois | `https?` |
| `{3}` `{2,4}` | exactement 3 fois, de 2 à 4 fois | `[0-9]{5}` : un code postal |
| `(ab|cd)` | l'un ou l'autre | `(erreur|echec)` |
| `\.` | un vrai point (échappé) | `192\.168` |

## 2. `grep` : chercher

```
grep "erreur" /var/log/syslog            # les lignes qui contiennent « erreur »
grep -i "erreur" fichier                 # sans tenir compte de la casse
grep -v "^#" /etc/ssh/sshd_config        # les lignes qui NE commencent PAS par #
grep -n "root" /etc/passwd               # avec les numéros de ligne
grep -c "Failed password" auth.log       # compte les lignes
grep -r "TODO" ~/projet                  # dans tout un dossier
grep -E "^[a-z]+:x:[0-9]{4}:" /etc/passwd    # -E : regex étendues (+, ?, {}, |)
grep -oE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+" auth.log   # -o : seulement ce qui correspond
```

## 3. `sed` : remplacer

```
sed 's/ancien/nouveau/' fichier          # remplace la 1re occurrence de chaque ligne
sed 's/ancien/nouveau/g' fichier         # g : toutes les occurrences
sed -i 's/Port 22/Port 2222/' sshd_config    # -i : modifie le fichier lui-même
sed -i.bak 's/a/b/g' fichier             # … en gardant une copie fichier.bak
sed '/^#/d' fichier                      # supprime les lignes de commentaire
sed -n '5,10p' fichier                   # affiche les lignes 5 à 10
sed -E 's/([0-9]+)-([0-9]+)/\2-\1/' f    # \1, \2 : les groupes capturés
```

## 4. `awk` : travailler en colonnes

`awk` découpe chaque ligne en champs : `$1`, `$2`… et `$0` pour la ligne entière.

```
awk '{print $1}' fichier                 # la première colonne
awk -F: '{print $1, $7}' /etc/passwd     # -F: : le séparateur est « : »
awk -F: '$3 >= 1000 {print $1}' /etc/passwd      # condition : les comptes « humains »
df -h | awk 'NR > 1 {print $5, $6}'      # NR : numéro de ligne (on saute l'en-tête)
awk '{somme += $2} END {print somme}' ventes.txt # un total
```

## 5. Combiner avec les tubes

```
# Les 5 adresses IP qui échouent le plus à se connecter en SSH
grep "Failed password" /var/log/auth.log \
  | grep -oE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+" \
  | sort | uniq -c | sort -rn | head -5

# Les utilisateurs dont le shell est bash, triés
grep "bash$" /etc/passwd | cut -d: -f1 | sort

# Nombre de requêtes par code HTTP dans un journal nginx
awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn
```

Le couple `sort | uniq -c | sort -rn` (trier, compter les doublons, classer) est le réflexe de base pour analyser un journal.

!tuto Analyser les tentatives d'intrusion

=== bash-ssh-cron | Bash : SSH, tâches planifiées et sauvegardes | m
## 1. SSH : administrer à distance

**SSH** ouvre un terminal chiffré sur une machine distante. C'est l'outil quotidien de l'administrateur.

```
ssh lea@192.168.1.50                 # connexion
ssh -p 2222 lea@serveur.exemple.fr   # sur un autre port que 22
ssh lea@serveur "df -h /"            # exécute une seule commande et revient
exit                                 # ferme la session
```

## 2. Les clés SSH

Plutôt qu'un mot de passe, on utilise une **paire de clés** : la clé **privée** reste sur ton poste, la clé **publique** est déposée sur le serveur.

```
ssh-keygen -t ed25519 -C "lea@portable"     # crée ~/.ssh/id_ed25519 (privée) et .pub (publique)
ssh-copy-id lea@192.168.1.50                # dépose la clé publique sur le serveur
ssh lea@192.168.1.50                        # plus de mot de passe demandé
```

La clé publique est ajoutée au fichier `~/.ssh/authorized_keys` du serveur.

!attention La clé privée ne se partage jamais | Ne l'envoie pas, ne la copie pas dans un dépôt Git, ne la colle dans aucun site. Protège-la par une phrase de passe. Si elle fuit, retire immédiatement la clé publique correspondante de tous les serveurs.

Le fichier `~/.ssh/config` évite de retaper les options :

```
Host web
    HostName 192.168.1.50
    User lea
    Port 2222
```

```
ssh web                               # équivaut à ssh -p 2222 lea@192.168.1.50
```

## 3. Sécuriser le serveur SSH

Dans `/etc/ssh/sshd_config`, puis `sudo systemctl restart ssh` :

```
PermitRootLogin no               # pas de connexion directe en root
PasswordAuthentication no        # clés uniquement
Port 2222                        # facultatif : réduit le bruit des robots
AllowUsers lea admin             # liste blanche
```

## 4. Copier des fichiers

```
scp rapport.pdf lea@web:/home/lea/              # copie vers le serveur
scp lea@web:/var/log/syslog ./                  # copie depuis le serveur
rsync -avz --delete site/ lea@web:/var/www/site/    # synchronise : ne transfère que les différences
```

`rsync` est l'outil des sauvegardes : `-a` conserve droits et dates, `-v` détaille, `-z` compresse, `--delete` supprime à l'arrivée ce qui a disparu au départ.

## 5. `cron` : planifier

```
crontab -e                       # édite les tâches de l'utilisateur
crontab -l                       # les affiche
```

Chaque ligne : cinq champs de date, puis la commande.

```
# minute  heure  jour-du-mois  mois  jour-de-la-semaine   commande
  30      2      *             *     *                    /usr/local/bin/sauvegarde.sh
  0       *      *             *     *                    /usr/local/bin/verif-disque.sh
  */15    *      *             *     *                    /usr/local/bin/ping-serveurs.sh
  0       8      *             *     1-5                  /usr/local/bin/rapport.sh
  0       3      1             *     *                    /usr/local/bin/archivage.sh
```

| Écriture | Signifie |
| `*` | toutes les valeurs |
| `*/15` | toutes les 15 unités |
| `1-5` | de 1 à 5 (lundi à vendredi) |
| `1,15` | le 1 et le 15 |

Lecture : la première ligne s'exécute tous les jours à 2 h 30 ; la troisième toutes les 15 minutes ; la quatrième à 8 h du lundi au vendredi.

!attention Dans cron, l'environnement est minimal | Utilise des **chemins absolus** pour les commandes et les fichiers, et redirige les sorties vers un journal : `… >> /var/log/sauvegarde.log 2>&1`.

!tuto Un script de sauvegarde complet
# Archiver avec la date dans le nom
```
#!/bin/bash
set -euo pipefail
SOURCE="/var/www/site"
DESTINATION="/sauvegardes"
ARCHIVE="$DESTINATION/site-$(date +%F).tar.gz"

mkdir -p "$DESTINATION"
tar -czf "$ARCHIVE" -C "$(dirname "$SOURCE")" "$(basename "$SOURCE")"
echo "Archive créée : $ARCHIVE ($(du -h "$ARCHIVE" | cut -f1))"
```
# Supprimer les archives de plus de 7 jours
```
find "$DESTINATION" -name "site-*.tar.gz" -mtime +7 -delete
```
# Copier sur un autre serveur
Une sauvegarde qui reste sur la même machine n'en est pas une.
```
rsync -az "$DESTINATION/" sauvegarde@nas:/volume1/sauvegardes/site/
```
# Planifier et journaliser
```
# crontab -e
30 2 * * * /usr/local/bin/sauvegarde.sh >> /var/log/sauvegarde.log 2>&1
```
# La règle 3-2-1
**3** copies des données, sur **2** supports différents, dont **1** hors site. Et une sauvegarde n'existe que si on a **testé sa restauration**.
!fin

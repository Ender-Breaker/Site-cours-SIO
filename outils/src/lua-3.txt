=== lua-erreurs-modules | Lua : erreurs, modules et bibliothèques standard | m
## 1. Provoquer une erreur : `error` et `assert`

```run err
local function racine(x)
  if x < 0 then
    error("nombre négatif interdit : " .. x)
  end
  return math.sqrt(x)
end
print(racine(16))
print(racine(-4))        -- le programme s'arrête ici
print("jamais affiché")
```

`assert(condition, message)` provoque une erreur si la condition est fausse, sinon renvoie la condition. C'est le raccourci habituel pour vérifier une hypothèse :

```run err
local age = assert(tonumber("17"), "âge invalide")
print(age)
local autre = assert(tonumber("abc"), "âge invalide")
```

## 2. Attraper une erreur : `pcall`

`pcall(f, arguments…)` (*protected call*) appelle `f` en mode protégé. Il renvoie `true` suivi des résultats, ou `false` suivi du message d'erreur. Le programme **continue** dans les deux cas : c'est le `try / catch` de Lua.

```run
local function diviser(a, b)
  if b == 0 then error("division par zéro") end
  return a / b
end

local ok, resultat = pcall(diviser, 10, 2)
print(ok, resultat)
local ok2, message = pcall(diviser, 10, 0)
print(ok2, message)
print("le programme continue")

if not pcall(function() local t = nil; return t.x end) then
  print("erreur attrapée : on a indexé nil")
end
```

L'erreur peut être n'importe quelle valeur, par exemple une table qui décrit le problème. Le second argument de `error` (le niveau `0`) retire le préfixe « fichier:ligne » du message :

```run
local ok, e = pcall(function() error({ code = 404, texte = "introuvable" }) end)
print(ok, e.code, e.texte)
print(pcall(error, "message nu", 0))
```

## 3. La convention `nil, message`

Pour une erreur **prévisible** (fichier absent, saisie invalide), les fonctions Lua ne lèvent pas d'erreur : elles renvoient `nil` suivi d'un message. L'appelant teste le premier résultat.

```run
local function lireAge(texte)
  local n = tonumber(texte)
  if not n then return nil, "ce n'est pas un nombre" end
  if n < 0 or n > 130 then return nil, "âge impossible" end
  return n
end

for _, saisie in ipairs({ "17", "abc", "250" }) do
  local age, err = lireAge(saisie)
  if age then print("âge valide :", age) else print("refusé :", err) end
end
```

!info Quelle méthode choisir ? | `nil, message` pour ce qui peut arriver normalement (mauvaise saisie). `error` pour un bug ou une situation qui ne devrait jamais arriver. `pcall` à l'endroit où tu sais quoi faire de l'erreur.

## 4. La bibliothèque `math`

```run
print(math.floor(3.7), math.ceil(3.2))      -- arrondis bas et haut : 3  4
print(math.floor(3.5 + 0.5))                -- arrondi au plus proche : 4

print(math.abs(-5), math.sqrt(49), math.pi)
print(math.huge, -math.huge)                -- plus et moins l'infini
print(math.tointeger(5.0), 7 // 1)          -- flottant → entier
print(math.random(1, 6))                    -- entier au hasard entre 1 et 6
print(math.random())                        -- flottant entre 0 et 1
```

## 5. `os` et `io`

```run
print(os.time())                       -- secondes depuis le 1er janvier 1970
print(os.date("%d/%m/%Y %H:%M"))       -- date mise en forme
local debut = os.clock()               -- temps processeur, pour chronométrer
local s = 0
for i = 1, 1000000 do s = s + i end
print(s, os.clock() - debut >= 0)
```

Sur un ordinateur, `io` lit et écrit aussi des fichiers. Ce code ne fonctionne pas dans le navigateur (pas de disque), mais c'est celui que tu écriras en vrai :

```
local f, err = io.open("scores.txt", "w")     -- "r" lire, "w" écrire, "a" ajouter
if not f then error(err) end
f:write("Léa 120\n")
f:close()

for ligne in io.lines("scores.txt") do        -- lit le fichier ligne par ligne
  print(ligne)
end
```

Remarque la convention `nil, message` de `io.open`, et son raccourci : `local f = assert(io.open("scores.txt"))`.

## 6. Les modules

Un module est un fichier qui **renvoie une table** de fonctions. On le charge avec `require`, qui exécute le fichier une seule fois et garde le résultat en mémoire.

```
-- fichier geometrie.lua
local M = {}

local function carre(x) return x * x end          -- privé : non exporté

function M.aireCercle(r) return math.pi * carre(r) end
function M.aireRectangle(l, h) return l * h end

return M
```

```
-- fichier main.lua
local geo = require("geometrie")       -- sans l'extension .lua
print(geo.aireRectangle(3, 4))
```

Dans le navigateur il n'y a qu'un seul fichier, mais le principe se teste très bien avec un bloc `do … end` :

```run
local geo
do
  local M = {}
  local function carre(x) return x * x end
  function M.aireCercle(r) return math.pi * carre(r) end
  function M.aireRectangle(l, h) return l * h end
  geo = M
end
print(geo.aireRectangle(3, 4))
print(string.format("%.2f", geo.aireCercle(1)))
print(carre)          -- nil : la fonction privée est invisible
```

=== lua-coroutines | Lua : les coroutines | d
Une **coroutine** est une fonction qui peut se **mettre en pause** au milieu de son exécution, rendre la main, puis **reprendre exactement là où elle s'était arrêtée**, avec toutes ses variables locales intactes. C'est une spécialité de Lua, très utilisée dans les jeux pour écrire des séquences (« avance, attends 2 secondes, tire, attends… ») comme un simple script.

## 1. Créer, lancer, suspendre

```run
local co = coroutine.create(function()
  print("étape 1")
  coroutine.yield()            -- pause : rend la main
  print("étape 2")
  coroutine.yield()
  print("étape 3")
end)

print(coroutine.status(co))    -- suspended : créée mais pas encore lancée
coroutine.resume(co)           -- exécute jusqu'au premier yield
print("-- retour au programme principal")
coroutine.resume(co)
coroutine.resume(co)
print(coroutine.status(co))    -- dead : terminée
print(coroutine.resume(co))    -- false   cannot resume dead coroutine
```

| Fonction | Rôle |
| `coroutine.create(f)` | crée la coroutine (sans la lancer) |
| `coroutine.resume(co, …)` | lance ou reprend ; renvoie `true` + les valeurs, ou `false` + l'erreur |
| `coroutine.yield(…)` | met en pause, depuis l'intérieur |
| `coroutine.status(co)` | `suspended`, `running`, `dead` |
| `coroutine.wrap(f)` | crée la coroutine et renvoie une fonction qui la reprend |

## 2. Échanger des valeurs

`yield` peut **envoyer** des valeurs à celui qui a fait `resume`, et `resume` peut en **envoyer** à la coroutine.

```run
local co = coroutine.create(function(a)
  print("reçu au départ :", a)
  local b = coroutine.yield(a * 2)        -- envoie a*2, puis attend
  print("reçu à la reprise :", b)
  return "terminé"
end)

print(coroutine.resume(co, 10))    -- true   20
print(coroutine.resume(co, 99))    -- true   terminé
```

## 3. Les générateurs avec `coroutine.wrap`

Un **générateur** produit des valeurs une par une, à la demande. `coroutine.wrap` renvoie directement une fonction : c'est un itérateur tout prêt pour `for … in`.

```run
local function fibonacci(limite)
  return coroutine.wrap(function()
    local a, b = 0, 1
    while a <= limite do
      coroutine.yield(a)
      a, b = b, a + b
    end
  end)
end

for n in fibonacci(100) do io.write(n, " ") end
print()
```

La suite pourrait être infinie : le générateur ne calcule que ce qu'on lui demande.

```run
local function compteur()
  return coroutine.wrap(function()
    local n = 0
    while true do n = n + 1; coroutine.yield(n) end    -- boucle infinie… mais en pause
  end)
end
local suivant = compteur()
print(suivant(), suivant(), suivant())
```

## 4. Les coroutines dans un jeu

Sans coroutine, une séquence d'actions oblige à gérer des états et des minuteurs. Avec, on écrit la séquence de haut en bas, et on reprend la coroutine une fois par image.

```run
local function attendre(images)
  for _ = 1, images do coroutine.yield() end
end

local boss = coroutine.wrap(function()
  while true do
    print("  le boss avance")
    attendre(2)
    print("  le boss tire")
    attendre(1)
  end
end)

for image = 1, 8 do            -- la boucle de jeu : une reprise par image
  io.write("image ", image, "\n")
  boss()
end
```

!attention Ce n'est pas du parallélisme | Une seule coroutine s'exécute à la fois, et elle ne s'interrompt **que** là où elle appelle `yield`. Il n'y a donc ni course critique ni verrou à gérer, contrairement aux threads du système.

!tuto Un producteur et un consommateur
# Le producteur génère des commandes
```run
local producteur = coroutine.wrap(function()
  for _, article in ipairs({ "clavier", "souris", "écran" }) do
    coroutine.yield(article)
  end
end)
print(producteur(), producteur(), producteur(), producteur())
```
# Le consommateur les traite une à une
Quand le producteur est terminé, il renvoie `nil` : la boucle `for` s'arrête toute seule.
```run
local function commandes()
  return coroutine.wrap(function()
    for _, article in ipairs({ "clavier", "souris", "écran" }) do
      coroutine.yield(article)
    end
  end)
end
local n = 0
for article in commandes() do
  n = n + 1
  print("commande " .. n .. " : " .. article)
end
```
# Un filtre entre les deux
On enchaîne les générateurs comme des tuyaux (pipes) du shell.
```run
local function nombres(n)
  return coroutine.wrap(function() for i = 1, n do coroutine.yield(i) end end)
end
local function pairs_seulement(source)
  return coroutine.wrap(function()
    for v in source do if v % 2 == 0 then coroutine.yield(v) end end
  end)
end
for v in pairs_seulement(nombres(10)) do io.write(v, " ") end
print()
```

=== lua-jeux | Lua : créer un jeu | d
Tous les moteurs de jeu fonctionnent de la même façon : ils appellent **tes** fonctions à des moments précis. Avec **LÖVE** : `love.load()` au démarrage, puis `love.update(dt)` et `love.draw()` à chaque image. Le labo du site reprend exactement ce principe, avec `setup`, `update` et `draw`.

!info Où tester ? | Les jeux ont besoin d'un écran : ils se lancent dans le [bac à sable du labo](labo-lua.html#libre). Copie les exemples de ce chapitre et modifie-les.

## 1. La boucle de jeu

```
local x = 0

function setup()            -- appelée une fois au démarrage
  x = 50
end

function update(dt)         -- 60 fois par seconde : la logique (déplacer, tester)
  x = x + 2
end

function draw()             -- 60 fois par seconde : l'affichage, rien d'autre
  effacer("black")
  rect(x, 150, 30, 30, "gold")
end
```

`dt` est le temps écoulé depuis l'image précédente, en secondes (environ 0,016). Multiplier une vitesse par `dt` donne un mouvement en **pixels par seconde**, identique quel que soit l'ordinateur : `x = x + 120 * dt`.

## 2. L'API de dessin et d'entrées

| Fonction | Rôle |
| `effacer(couleur)` | remplit tout l'écran |
| `rect(x, y, largeur, hauteur, couleur)` | rectangle plein (x, y = coin haut gauche) |
| `cercle(x, y, rayon, couleur)` | disque (x, y = centre) |
| `ligne(x1, y1, x2, y2, couleur)` | segment |
| `texte(message, x, y, taille, couleur)` | texte |
| `touche("droite")` | vrai **tant que** la touche est enfoncée |
| `toucheAppuyee("espace")` | vrai **une seule image**, au moment de l'appui |
| `sourisX()`, `sourisY()`, `clic()` | position de la souris, clic |
| `hasard(a, b)` | entier au hasard entre a et b |
| `LARGEUR`, `HAUTEUR` | 480 et 320 |

L'origine (0, 0) est en **haut à gauche** : `y` augmente vers le **bas**. Touches : `gauche`, `droite`, `haut`, `bas`, `espace`, `entree`, les lettres et les chiffres.

## 3. Déplacer un personnage

```
local joueur = { x = 220, y = 260, l = 40, h = 40, vitesse = 200 }

function update(dt)
  if touche("gauche") then joueur.x = joueur.x - joueur.vitesse * dt end
  if touche("droite") then joueur.x = joueur.x + joueur.vitesse * dt end
  joueur.x = math.max(0, math.min(LARGEUR - joueur.l, joueur.x))   -- reste dans l'écran
end

function draw()
  effacer("#16182b")
  rect(joueur.x, joueur.y, joueur.l, joueur.h, "deepskyblue")
end
```

## 4. Gravité et saut

La vitesse verticale `vy` augmente à chaque image (la gravité) ; un saut lui donne une valeur négative (vers le haut).

```
local y, vy, SOL = 260, 0, 260

function update(dt)
  if toucheAppuyee("espace") and y >= SOL then vy = -9 end   -- saut seulement au sol
  vy = vy + 0.5                -- gravité
  y = y + vy
  if y > SOL then y, vy = SOL, 0 end
end
```

## 5. Collisions

Deux rectangles se touchent s'ils se chevauchent sur les deux axes. Cette fonction (collision **AABB**) sert dans presque tous les jeux 2D :

```run
local function collision(a, b)
  return a.x < b.x + b.l and b.x < a.x + a.l
     and a.y < b.y + b.h and b.y < a.y + a.h
end
local joueur = { x = 100, y = 100, l = 40, h = 40 }
print(collision(joueur, { x = 130, y = 120, l = 20, h = 20 }))   -- true : se chevauchent
print(collision(joueur, { x = 300, y = 100, l = 20, h = 20 }))   -- false : trop loin
```

Pour deux cercles : ils se touchent si la distance entre les centres est inférieure à la somme des rayons.

```run
local function touche_cercles(a, b)
  local dx, dy = a.x - b.x, a.y - b.y
  return dx * dx + dy * dy < (a.r + b.r) ^ 2      -- sans racine carrée : plus rapide
end
print(touche_cercles({ x = 0, y = 0, r = 10 }, { x = 12, y = 9, r = 6 }))
```

## 6. Beaucoup d'objets : une table de tables

Ennemis, projectiles, pièces : on les range dans une liste. Pour **supprimer** pendant le parcours, on parcourt **à l'envers**, sinon `table.remove` décale les éléments et on en saute.

```run
local tirs = { { y = 50 }, { y = -5 }, { y = 120 }, { y = -30 } }
for i = #tirs, 1, -1 do                    -- à l'envers !
  tirs[i].y = tirs[i].y - 10
  if tirs[i].y < 0 then table.remove(tirs, i) end
end
print(#tirs .. " tirs encore à l'écran")
```

## 7. Les états du jeu

Menu, partie, fin de partie : une variable d'état décide quoi mettre à jour et quoi dessiner.

```
local etat, score = "menu", 0

function update(dt)
  if etat == "menu" then
    if toucheAppuyee("espace") then etat, score = "jeu", 0 end
  elseif etat == "jeu" then
    score = score + 1
    if score > 300 then etat = "fin" end
  elseif etat == "fin" and toucheAppuyee("espace") then
    etat = "menu"
  end
end

function draw()
  effacer("black")
  if etat == "menu" then texte("ESPACE pour jouer", 130, 150, 24, "white")
  elseif etat == "jeu" then texte("Score : " .. score, 16, 16, 24, "white")
  else texte("Perdu ! Score : " .. score, 130, 150, 24, "tomato") end
end
```

=== lua-ecosysteme | Lua en vrai : Roblox, LÖVE, Neovim et bonnes pratiques | m
Tu connais maintenant le langage. Ce chapitre montre où et comment il s'utilise réellement, les différences à connaître selon l'environnement, et les habitudes des développeurs Lua.

## 1. LÖVE (love2d)

LÖVE est un moteur 2D gratuit. Un jeu est un dossier qui contient un fichier `main.lua` ; on le lance avec la commande `love dossier`.

```
local joueur = { x = 100, y = 100 }

function love.load()                       -- ≈ setup()
  love.window.setTitle("Mon jeu")
end

function love.update(dt)                   -- ≈ update(dt)
  if love.keyboard.isDown("right") then joueur.x = joueur.x + 200 * dt end
end

function love.draw()                       -- ≈ draw()
  love.graphics.setColor(1, 0.8, 0)        -- couleurs de 0 à 1
  love.graphics.rectangle("fill", joueur.x, joueur.y, 40, 40)
  love.graphics.print("Score : 0", 10, 10)
end

function love.keypressed(touche)           -- ≈ toucheAppuyee
  if touche == "escape" then love.event.quit() end
end
```

| Dans le labo | Avec LÖVE |
| `setup()` | `love.load()` |
| `update(dt)` / `draw()` | `love.update(dt)` / `love.draw()` |
| `rect(x, y, l, h, c)` | `love.graphics.rectangle("fill", x, y, l, h)` |
| `cercle(x, y, r, c)` | `love.graphics.circle("fill", x, y, r)` |
| `touche("droite")` | `love.keyboard.isDown("right")` |
| `hasard(a, b)` | `love.math.random(a, b)` |

## 2. Roblox et Luau

Roblox Studio utilise **Luau**, un Lua 5.1 enrichi (types optionnels, `+=`, `continue`). Les scripts manipulent des objets du jeu et réagissent à des **événements**.

```
local Players = game:GetService("Players")          -- un service du moteur
local piece = script.Parent                         -- l'objet auquel le script est attaché

piece.Touched:Connect(function(autre)               -- événement : quelque chose touche la pièce
  local joueur = Players:GetPlayerFromCharacter(autre.Parent)
  if joueur then
    joueur.leaderstats.Pieces.Value += 1            -- += existe en Luau
    piece:Destroy()
  end
end)

task.wait(2)                                        -- attend 2 secondes (une coroutine !)
print("2 secondes plus tard")
```

Ce que tu reconnais : les deux-points des méthodes, une fonction anonyme passée en argument (une closure), et `task.wait` qui met le script en pause grâce aux coroutines.

| Lua 5.4 | Luau (Roblox) |
| `i = i + 1` | `i += 1` accepté |
| pas de `continue` | `continue` existe |
| `//` division entière | `//` existe aussi |
| `local x <const>` | pas de `<const>` |
| pas de types | `local n: number = 5` (facultatif) |
| `goto` | pas de `goto` |

## 3. Les versions de Lua

| Version | Où | Différence marquante |
| 5.1 | LuaJIT, LÖVE, Neovim, base de Luau | pas d'entiers séparés, `unpack` global, pas de `//` |
| 5.3 / 5.4 | Lua officiel, ce site | entiers 64 bits, `//`, opérateurs binaires, `<const>` |

En pratique : en 5.1, `10 / 2` affiche `5` et non `5.0`, et `table.unpack` s'appelle `unpack`.

## 4. Configurer avec Lua : Neovim, nginx, Wireshark

Beaucoup de logiciels utilisent Lua comme langage de **configuration et d'extension**, ce qui intéresse aussi l'option SISR. Un fichier de configuration Neovim n'est qu'un script qui remplit des tables :

```
vim.opt.number = true                    -- numéros de ligne
vim.opt.tabstop = 2
vim.keymap.set("n", "<leader>w", ":write<CR>")   -- un raccourci clavier
```

Avec OpenResty, on écrit en Lua des règles directement dans le serveur web nginx ; Wireshark, HAProxy, Redis et les pare-feu applicatifs acceptent aussi des scripts Lua.

## 5. Opérateurs binaires

Utiles pour les masques (réseau, droits, drapeaux d'un jeu) :

```run
print(6 & 3, 6 | 3, 6 ~ 3)        -- ET 2, OU 7, OU exclusif 5
print(1 << 4, 256 >> 2, ~0)       -- décalages : 16, 64 ; NON : -1
local LECTURE, ECRITURE, EXECUTION = 4, 2, 1
local droits = LECTURE | EXECUTION
print(droits, droits & ECRITURE ~= 0, droits & LECTURE ~= 0)
print(string.format("%d.%d", (192 << 8 | 168) >> 8, (192 << 8 | 168) & 0xFF))
```

## 6. Les bonnes pratiques

- **`local` partout**, y compris pour les fonctions et les modules (`local M = {}`).
- Des noms explicites ; `_` pour une valeur qu'on ignore (`for _, v in ipairs(t)`).
- Mettre en cache dans une locale ce qu'on utilise souvent dans une boucle : `local floor = math.floor`.
- Construire les longues chaînes avec `table.concat`, jamais avec `..` dans une boucle.
- Parcourir une liste avec `ipairs` ou `for i = 1, #t` ; un dictionnaire avec `pairs`.
- Tester l'absence avec `if x == nil` quand `false` est une valeur possible ; sinon `if not x`.
- Une erreur prévisible renvoie `nil, message` ; un bug lève `error`.

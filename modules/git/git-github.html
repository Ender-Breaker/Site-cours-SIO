Cours bonus

Ce cours est hors programme du BTS : il ne compte ni dans ta progression ni au classement. Il est là pour aller plus loin.

Un dépôt distant (*remote*) est une copie du dépôt hébergée sur un serveur : GitHub, GitLab ou le serveur de ton entreprise. C'est lui qui permet de sauvegarder, de partager et de collaborer.

1. Relier son dépôt à GitHub

git remote add origin https://github.com/lea/portfolio.git    # « origin » : nom donné au distant
git remote -v                                                 # vérifie
git push -u origin main          # premier envoi ; -u mémorise le lien
git push                         # les fois suivantes

Pour récupérer un projet existant, une seule commande :

git clone https://github.com/lea/portfolio.git

2. Envoyer et recevoir

CommandeEffet
git pushenvoie tes commits vers le distant
git fetchtélécharge les nouveautés sans modifier tes fichiers
git pullfetch puis fusion : met ta branche à jour
git clonecopie un dépôt distant complet
git pull                         # avant de commencer à travailler
# … commits …
git push                         # quand une étape est terminée
push refusé

Si quelqu'un a poussé avant toi, Git refuse ton push : fais d'abord git pull, règle un éventuel conflit, puis git push. N'utilise jamais git push --force sur une branche partagée : tu écraserais le travail des autres.

3. S'authentifier

GitHub n'accepte plus les mots de passe en ligne de commande. Deux solutions :

  • une clé SSH : ssh-keygen -t ed25519, puis on colle la clé publique (~/.ssh/id_ed25519.pub) dans les réglages de GitHub. L'adresse du dépôt devient git@github.com:lea/portfolio.git ;
  • un jeton d'accès personnel (*token*) utilisé à la place du mot de passe en HTTPS.

4. La pull request

Sur un projet d'équipe, personne ne pousse directement sur main. On propose ses modifications dans une pull request (PR ; *merge request* sur GitLab).

  1. Créer une branche et y commiter : git switch -c correction-menu.
  2. La pousser : git push -u origin correction-menu.
  3. Sur GitHub, ouvrir une pull request vers main : titre, description, captures.
  4. Un coéquipier relit le code, commente, demande des changements.
  5. Quand c'est validé, on fusionne la PR, puis on supprime la branche.

La relecture attrape les bugs, diffuse les connaissances dans l'équipe, et laisse une trace écrite des décisions.

6. Un bon README

Le README est la première chose que voit un recruteur ou un jury sur ton dépôt. Il s'écrit en Markdown :

# Gestion de parc informatique

Application web de suivi du matériel (projet de BTS SIO).

## Fonctionnalités
- Inventaire du matériel
- Suivi des interventions

## Installation
1. `git clone https://github.com/lea/parc.git`
2. `composer install`
3. Copier `.env.exemple` en `.env` et renseigner la base de données

## Technologies
PHP 8, MariaDB, Bootstrap

TutorielPublier un projet sur GitHub

Créer le dépôt en ligne

Sur GitHub : *New repository*, donne-lui un nom, laisse-le vide (sans README), puis copie son adresse.

Relier et pousser

git remote add origin https://github.com/ton-compte/portfolio.git
git push -u origin main

Travailler ensuite

git pull                                  # récupère ce qui a changé
git switch -c ajout-projets
# … modifications …
git add . && git commit -m "Ajoute la section projets"
git push -u origin ajout-projets
# puis : ouvrir une pull request sur GitHub
À retenir

git clone copie un dépôt distant ; git remote add origin URL relie un dépôt local.

git pull avant de travailler, git push après.

Jamais de push --force sur une branche partagée.

Pull request : une branche, une relecture, une fusion.

Authentification par clé SSH ou jeton.

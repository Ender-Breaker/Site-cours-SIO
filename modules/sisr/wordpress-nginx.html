Objectif : mettre en ligne un portfolio WordPress sur un serveur LEMP (Linux, Nginx, MariaDB/MySQL, PHP). Ce chapitre suit la méthode d'installation du cours, étape par étape. Les commandes sont exécutées en root (invite #).

Mots de passe

Dans les exemples, les mots de passe sont des espaces réservés (MonMotDePasseSQL). Utilise toujours des mots de passe forts et différents pour : le compte root Unix, le root SQL, l'utilisateur SQL du site et l'administrateur WordPress.

1. L'architecture LEMP

LettreBriqueRôle
LLinuxsystème d'exploitation du serveur
ENEginx (« engine x »)serveur web : reçoit les requêtes HTTP
MMariaDB / MySQLbase de données (contenu et réglages du site)
PPHPlangage dans lequel WordPress est écrit

Un site WordPress, c'est donc deux choses à sauvegarder : les fichiers (le dossier wordpress/) et la base de données (SQL + contenu).

2. Étape 1 — Récupérer WordPress

cd /var/www/
wget https://fr.wordpress.org/latest-fr_FR.tar.gz   # dernière version française
tar xvzf latest-fr_FR.tar.gz                        # extrait → dossier wordpress/

Le serveur web tourne sous l'utilisateur www-data. Il faut lui donner la propriété du dossier pour qu'il puisse y lire et écrire :

chown -R www-data:www-data wordpress/
ls -l      # le dossier wordpress doit appartenir à www-data

3. Étape 2 — Configurer Nginx

Par défaut, Nginx sert /var/www/html. On crée un site qui pointe vers wordpress.

cd /etc/nginx/sites-available/
cp default wordpress          # copie du modèle
nano wordpress                # remplacer :  root /var/www/html;
                              # par       :  root /var/www/wordpress;

server {
    listen 80 default_server;
    root /var/www/wordpress;
    index index.html index.php;
    server_name _;
    location / {
        try_files $uri $uri/ =404;
    }
}
  • root : le dossier racine du site. index : les pages servies par défaut.
  • Derrière un proxy, on récupère l'IP réelle du visiteur avec set_real_ip_from, real_ip_header X-Real-IP et real_ip_recursive on (déjà fournis dans les *snippets* du TP).
  • La page de connexion wp-login.php peut être protégée en n'autorisant que certaines adresses IP.

Activer le site

ln -s /etc/nginx/sites-available/wordpress /etc/nginx/sites-enabled/wordpress
cd ../sites-enabled/ ; ls -l     # wordpress -> /etc/nginx/sites-available/wordpress
rm default                       # on retire le site par défaut
nginx -t                         # teste la configuration
service nginx restart            # recharge Nginx
DossierRôle
sites-available/tous les sites disponibles (fichiers de configuration)
sites-enabled/les sites activés : des liens symboliques vers sites-available
Toujours tester

nginx -t vérifie la syntaxe avant de redémarrer : une erreur de configuration coupe le site.

4. Étape 3 — La base de données

mysql -u root -p     # le mot de passe « root SQL » est différent de root Unix

create database portfolio;
CREATE USER 'mon_user'@'localhost' IDENTIFIED BY 'MonMotDePasseSQL';
GRANT ALL PRIVILEGES ON portfolio.* TO 'mon_user'@'localhost';
FLUSH PRIVILEGES;
quit;
InstructionRôle
create databasecrée la base portfolio
CREATE USERcrée l'utilisateur SQL du site (≠ root SQL)
GRANT ALL PRIVILEGES ON portfolio.*lui donne tous les droits sur cette base uniquement
FLUSH PRIVILEGESapplique (propage) les droits

Principe du moindre privilège : le site n'utilise jamais le compte root SQL, seulement un utilisateur limité à sa propre base.

5. Étape 4 — Personnaliser wp-config

cd /var/www/wordpress/
cp wp-config-sample.php wp-config-sample.php.save   # TOUJOURS une sauvegarde d'abord !
nano wp-config-sample.php

// Boostage des capacités de WP
define('WP_MEMORY_LIMIT','256M');

// Utilisation derrière un proxy
if ($_SERVER['HTTP_X_FORWARDED_PROTO'] == 'https')
    $_SERVER['HTTPS']='on';

Puis service nginx restart. Le second bloc indique à WordPress qu'il est servi en HTTPS par un proxy placé devant le serveur.

6. Étape 5 — Finaliser dans le navigateur

  1. Ouvre ton domaine dans le navigateur.
  2. Renseigne l'accès à la base : nom portfolio, identifiant mon_user, mot de passe SQL, hôte localhost, préfixe de tables (ex. folio_).
  3. Renseigne le site : titre, identifiant et mot de passe d'administrateur WordPress (sans rapport avec root / mon_user), e-mail.
  4. Lance l'installation : c'est fait en quelques minutes.
Résumé express
  • LEMP = Linux + Nginx + MariaDB/MySQL + PHP.
  • wget + tar xvzf → chown -R www-data:www-data wordpress/.
  • Nginx : cp default wordpress, root /var/www/wordpress;, ln -s vers sites-enabled, rm default, nginx -t, service nginx restart.
  • SQL : create database, CREATE USER, GRANT … ON base.*, FLUSH PRIVILEGES.
  • wp-config : sauvegarde .save d'abord, puis WP_MEMORY_LIMIT et réglage proxy HTTPS.

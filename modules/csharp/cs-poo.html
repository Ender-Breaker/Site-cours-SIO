1. Classes et propriétés

Là où Java écrit des accesseurs getX / setX, C# a des propriétés : elles s'utilisent comme des attributs mais peuvent contenir du contrôle.

class Compte
{
    public string Titulaire { get; set; }            // propriété automatique
    public double Solde { get; private set; }        // lisible partout, modifiable dans la classe seulement

    private string _code;                            // attribut privé (convention : tiret bas)
    public string Code
    {
        get { return _code; }
        set { if (value.Length == 4) _code = value; }     // value : la valeur affectée
    }

    public Compte(string titulaire, double solde = 0)     // constructeur
    {
        Titulaire = titulaire;
        Solde = solde;
    }

    public void Deposer(double montant)
    {
        if (montant <= 0) throw new ArgumentException("Montant invalide");
        Solde += montant;
    }

    public override string ToString() => $"{Titulaire} : {Solde:F2} €";
}
var c = new Compte("Léa", 100);
c.Deposer(50);
c.Titulaire = "Léa Martin";          // appelle le set
Console.WriteLine(c.Solde);          // appelle le get
// c.Solde = 1000000;                // refusé : set privé
Console.WriteLine(c);                // appelle ToString

2. Héritage et interfaces

abstract class Forme
{
    public abstract double Aire();                        // à définir dans les filles
    public virtual string Nom() => "forme";               // virtual : redéfinissable
    public string Description() => $"{Nom()} d'aire {Aire():F2}";
}

class Rectangle : Forme                                   // « : » remplace extends
{
    private readonly double l, h;
    public Rectangle(double l, double h) { this.l = l; this.h = h; }
    public override double Aire() => l * h;               // override obligatoire
    public override string Nom() => "rectangle";
}

interface IExportable                                     // convention : un I devant le nom
{
    string VersCsv();
}

class Produit : IExportable                               // « : » remplace aussi implements
{
    public string Nom { get; set; }
    public double Prix { get; set; }
    public string VersCsv() => $"{Nom};{Prix}";
}

3. Les exceptions

try
{
    int n = int.Parse(Console.ReadLine());
    Console.WriteLine(100 / n);
}
catch (FormatException)
{
    Console.WriteLine("Il faut un nombre entier.");
}
catch (DivideByZeroException e)
{
    Console.WriteLine($"Erreur : {e.Message}");
}
finally
{
    Console.WriteLine("Fin");
}

Toutes les exceptions C# sont « non vérifiées » : pas de throws dans les signatures. Le bloc using ferme automatiquement une ressource, comme le try-with-resources de Java.

4. LINQ : interroger les collections

LINQ permet de filtrer, trier et agréger une collection comme on écrirait une requête SQL. C'est l'équivalent des streams de Java.

using System.Linq;

var eleves = new List<Eleve>
{
    new Eleve("Léa", "SLAM", 15), new Eleve("Sam", "SISR", 9),
    new Eleve("Zoé", "SLAM", 18), new Eleve("Tom", "SISR", 12)
};

var admisSlam = eleves
    .Where(e => e.Option == "SLAM" && e.Note >= 10)       // filtre
    .OrderByDescending(e => e.Note)                       // tri
    .Select(e => e.Nom);                                  // projection
Console.WriteLine(string.Join(", ", admisSlam));          // Zoé, Léa

double moyenne = eleves.Average(e => e.Note);
int nbAdmis = eleves.Count(e => e.Note >= 10);
Eleve meilleur = eleves.MaxBy(e => e.Note);
bool tousAdmis = eleves.All(e => e.Note >= 10);
var parOption = eleves.GroupBy(e => e.Option);
foreach (var groupe in parOption)
    Console.WriteLine($"{groupe.Key} : {groupe.Count()} élèves");

5. Accéder à une base de données

Avec ADO.NET, le schéma est le même qu'en JDBC : connexion → commande paramétrée → lecteur.

using MySqlConnector;

string chaine = "Server=localhost;Database=parc;User ID=app;Password=…";
using var cnx = new MySqlConnection(chaine);
cnx.Open();

using var cmd = new MySqlCommand("SELECT nom, prix FROM materiel WHERE prix > @seuil", cnx);
cmd.Parameters.AddWithValue("@seuil", 100);               // paramètre : pas d'injection SQL

using var lecteur = cmd.ExecuteReader();
while (lecteur.Read())
    Console.WriteLine($"{lecteur.GetString("nom")} : {lecteur.GetDouble("prix")}");
Toujours des paramètres

Comme en PHP et en Java : ne construis jamais une requête en concaténant une saisie. Les paramètres @nom transmettent la saisie comme une donnée.

Dans les projets récents, on utilise souvent Entity Framework Core, un ORM : on manipule des objets et des requêtes LINQ, et il génère le SQL.

var chers = contexte.Materiels.Where(m => m.Prix > 100).OrderBy(m => m.Nom).ToList();

TutorielUne gestion de tickets d'assistance

Le modèle

enum Priorite { Basse, Normale, Urgente }

class Ticket
{
    public int Numero { get; }
    public string Titre { get; }
    public Priorite Priorite { get; }
    public bool Resolu { get; private set; }

    public Ticket(int numero, string titre, Priorite priorite)
    {
        Numero = numero; Titre = titre; Priorite = priorite;
    }
    public void Resoudre() => Resolu = true;
}

La liste et les requêtes LINQ

var tickets = new List<Ticket>
{
    new Ticket(1, "Imprimante hors ligne", Priorite.Normale),
    new Ticket(2, "Serveur de fichiers en panne", Priorite.Urgente),
    new Ticket(3, "Mot de passe oublié", Priorite.Basse)
};
tickets[2].Resoudre();

var aTraiter = tickets.Where(t => !t.Resolu).OrderByDescending(t => t.Priorite);
foreach (var t in aTraiter)
    Console.WriteLine($"#{t.Numero} [{t.Priorite}] {t.Titre}");
Console.WriteLine($"{tickets.Count(t => t.Resolu)} ticket(s) résolu(s)");

Cours bonus

Ce cours est hors programme du BTS : il ne compte pas dans ta progression ni au classement du programme, mais il a son propre classement bonus. Il est là pour aller plus loin.

L'assembleur est la forme lisible du code machine : une ligne par instruction du processeur. On n'a pas besoin de savoir en écrire pour faire de la rétro-ingénierie, mais il faut savoir en lire. Ce chapitre couvre le x86-64 (PC), en syntaxe Intel : instruction destination, source.

1. Les registres

Un registre est une minuscule case mémoire à l'intérieur du processeur.

RegistreRôle habituel
raxrésultat des calculs et valeur de retour d'une fonction
rdi, rsi, rdx, rcxles quatre premiers arguments d'une fonction (Linux)
rbx, r8 … r15usage général
rsppointeur de pile : le sommet de la pile
rbppointeur de base : le repère des variables locales
ripl'adresse de la prochaine instruction

eax désigne les 32 bits bas de rax, ax les 16 bits bas, al les 8 bits bas : c'est le même registre vu par une fenêtre plus étroite.

2. Les instructions essentielles

InstructionEffet
mov a, ba = b
add a, b / sub a, ba = a + b / a = a − b
inc a / dec aa++ / a--
imul a, ba = a × b
xor a, ba = a XOR b ; xor eax, eax met eax à zéro
and, or, shl, shropérations sur les bits, décalages
lea a, [b + c*4]calcule une adresse (ou fait une addition rapide)
cmp a, bcompare en calculant a − b, sans garder le résultat : positionne les drapeaux
test a, aa est-il nul ?
jmp ciblesaut inconditionnel
je / jnesaut si égal / si différent
jl, jle, jg, jgesaut si inférieur, inférieur ou égal, supérieur, supérieur ou égal
call fonctionappelle une fonction (empile l'adresse de retour)
retrevient à l'appelant
push a / pop aempile / dépile

Les crochets désignent la mémoire : mov eax, [rbp-4] lit la variable locale rangée 4 octets sous rbp.

3. Un simulateur pour s'entraîner

Ce mini-processeur exécute quelques instructions et affiche les registres après chaque ligne. Modifie le programme et relance.

function executer(programme) {
  const r = { eax: 0, ebx: 0, ecx: 0 };
  const val = x => (x in r ? r[x] : Number(x));
  const lignes = programme.trim().split("\n").map(l => l.trim());
  let egal = false, n = 0;
  for (let i = 0; i < lignes.length && n++ < 100; i++) {
    const [op, a, b] = lignes[i].replace(",", "").split(/\s+/);
    if (op === "mov") r[a] = val(b);
    else if (op === "add") r[a] += val(b);
    else if (op === "sub") r[a] -= val(b);
    else if (op === "imul") r[a] *= val(b);
    else if (op === "xor") r[a] ^= val(b);
    else if (op === "cmp") egal = val(a) === val(b);
    else if (op === "jne" && !egal) i = lignes.indexOf(a + ":");
    else if (op === "jmp") i = lignes.indexOf(a + ":");
    if (!op.endsWith(":")) console.log(lignes[i].padEnd(14), JSON.stringify(r));
  }
}
executer(`
mov eax, 5
mov ebx, 3
add eax, ebx
imul eax, 2
xor ebx, ebx
`);

4. Reconnaître une condition

    cmp   eax, 18            if (age >= 18) {
    jl    .sinon                 majeur();
    call  majeur             } else {
    jmp   .fin                   mineur();
.sinon:                      }
    call  mineur
.fin:

Le saut est l'inverse de la condition du code source : jl (« saute si inférieur ») saute par-dessus le bloc du if. Un cmp suivi d'un saut conditionnel, c'est un if.

5. Reconnaître une boucle

    mov   ecx, 0             for (int i = 0; i < 10; i++) {
.boucle:                         total += i;
    cmp   ecx, 10            }
    jge   .fin
    add   eax, ecx
    inc   ecx
    jmp   .boucle
.fin:

Un saut vers l'arrière signale une boucle. Essaie dans le simulateur : la somme de 1 à 4.

function executer(programme) {
  const r = { eax: 0, ecx: 0 };
  const val = x => (x in r ? r[x] : Number(x));
  const lignes = programme.trim().split("\n").map(l => l.trim());
  let egal = false, n = 0;
  for (let i = 0; i < lignes.length && n++ < 200; i++) {
    const [op, a, b] = lignes[i].replace(",", "").split(/\s+/);
    if (op === "mov") r[a] = val(b);
    else if (op === "add") r[a] += val(b);
    else if (op === "cmp") egal = val(a) === val(b);
    else if (op === "jne" && !egal) i = lignes.indexOf(a + ":");
  }
  console.log(JSON.stringify(r));
}
executer(`
mov eax, 0
mov ecx, 1
boucle:
add eax, ecx
add ecx, 1
cmp ecx, 5
jne boucle
`);

6. Un appel de fonction

    mov   edi, 3             ; 1er argument
    mov   esi, 4             ; 2e argument
    call  addition           ; résultat dans eax
    ...
addition:
    push  rbp                ; prologue : sauvegarde le repère de l'appelant
    mov   rbp, rsp
    mov   eax, edi
    add   eax, esi
    pop   rbp                ; épilogue
    ret

Quand tu vois push rbp / mov rbp, rsp, une fonction commence. Ce qui est dans rdi, rsi, rdx juste avant un call ce sont ses arguments ; ce qui est dans rax juste après, son résultat. C'est la convention d'appel (ici System V, celle de Linux ; Windows utilise rcx, rdx, r8, r9).

7. Du C à l'assembleur, et retour

Le meilleur exercice : écrire trois lignes de C, regarder ce que le compilateur en fait (gcc -S -O0 -masm=intel fichier.c, ou le site Compiler Explorer), puis recommencer avec -O2. Un décompilateur comme Ghidra fait le chemin inverse et propose :

bool verifier(char *saisie) {
    return strcmp(saisie, "sio2026") == 0;
}

Les noms (verifier, saisie) sont ceux que l'analyste a donnés : renommer les fonctions et les variables au fur et à mesure qu'on les comprend, c'est le cœur du travail.

TutorielLire une fonction inconnue

Le désassemblage

mystere:
    mov   eax, edi
    imul  eax, edi
    add   eax, 1
    ret

Ligne par ligne

edi est le premier argument, appelons-le x. eax = x, puis eax = eax × x, puis eax = eax + 1, puis retour avec le résultat dans eax.

La réponse

int mystere(int x) { return x * x + 1; }. Vérifie avec le simulateur : remplace edi par une valeur.

let eax = 0; const edi = 6;
eax = edi;
eax = eax * edi;
eax = eax + 1;
console.log(eax);
À retenir

Syntaxe Intel : instruction destination, source.

rax : résultat ; rdi, rsi, rdx : arguments ; rsp / rbp : la pile ; rip : l'instruction suivante.

cmp + saut conditionnel = un if ; un saut vers l'arrière = une boucle ; call / ret = une fonction.

[…] = un accès à la mémoire.

On comprend en renommant petit à petit.

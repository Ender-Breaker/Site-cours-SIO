Cours bonus

Ce cours est hors programme du BTS : il ne compte pas dans ta progression ni au classement du programme, mais il a son propre classement bonus. Il est là pour aller plus loin.

Durcir (*hardening*) un système, c'est réduire tout ce qu'un attaquant pourrait utiliser : comptes, services, droits, logiciels. Un système fraîchement installé est configuré pour être pratique, pas pour être sûr.

Le compte root (UID 0) peut tout. Un attaquant qui obtient un compte ordinaire cherche à devenir root : c'est l'élévation de privilèges.

2. Les droits sur les fichiers

ls -l /etc/shadow                # -rw-r----- root shadow : les empreintes des mots de passe
chmod 600 ~/.ssh/id_ed25519      # une clé privée n'est lisible que par son propriétaire
chmod 640 /var/www/site/.env     # un fichier de secrets n'est jamais lisible par « les autres »
chmod o-w script.sh              # retirer l'écriture pour tous
Erreur fréquenteRisque
Fichier en 777n'importe qui peut le modifier : si root l'exécute, c'est gagné pour l'attaquant
Script lancé par root (cron) mais modifiable par un utilisateurélévation de privilèges
Fichier de configuration avec mot de passe, lisible par tousfuite de secret
Bit SUID sur un programme inutilele programme s'exécute avec les droits de son propriétaire (souvent root)
Dossier personnel lisible par tousfuite de données
find / -perm -4000 -type f 2>/dev/null       # liste les programmes SUID : à passer en revue
find /var/www -perm -o+w -type f             # fichiers modifiables par tout le monde

3. Réduire la surface

systemctl list-units --type=service --state=running     # ce qui tourne
sudo systemctl disable --now cups                       # arrêter et désactiver l'inutile
ss -tulpn                                               # ce qui écoute
apt list --installed | wc -l                            # moins de paquets = moins de failles

Règle : ce qui n'est pas installé ne peut pas être attaqué. Un serveur de base de données n'a besoin ni d'interface graphique, ni de compilateur, ni de serveur d'impression.

4. Mettre à jour

La majorité des intrusions exploitent une faille pour laquelle un correctif existait depuis des semaines.

sudo apt update && sudo apt upgrade              # Debian / Ubuntu
sudo apt install unattended-upgrades             # correctifs de sécurité automatiques

Sous Windows : Windows Update, et WSUS ou Intune pour gérer un parc. On tient un inventaire : on ne peut pas mettre à jour ce qu'on ne sait pas posséder.

Observateur d'événements Windows, journal Sécurité4624 connexion réussie, 4625 échec, 4720 création de compte
grep "Failed password" /var/log/auth.log | wc -l
last -n 10                       # dernières connexions réussies
lastb -n 10                      # dernières connexions échouées
sudo journalctl -p err -b        # erreurs depuis le démarrage

Les journaux sont envoyés vers un autre serveur : un attaquant devenu root efface ses traces sur la machine compromise.

7. Les référentiels

On ne durcit pas au hasard : on suit une liste. Les guides de l'ANSSI (GNU/Linux, Active Directory, hygiène informatique) et les CIS Benchmarks donnent, système par système, les réglages recommandés. Des outils comme Lynis (Linux) contrôlent automatiquement l'écart avec ces recommandations.

TutorielAuditer un serveur Linux en dix minutes

Qui peut se connecter et qui est administrateur ?

grep -v "nologin\|false" /etc/passwd | cut -d: -f1
getent group sudo

Qu'est-ce qui est exposé ?

ss -tulpn
sudo ufw status verbose

Les secrets sont-ils protégés ?

find /var/www /home -name ".env" -o -name "*.key" | xargs ls -l

Quelqu'un a-t-il essayé d'entrer ?

grep "Failed password" /var/log/auth.log | grep -oE "[0-9]+(\.[0-9]+){3}" | sort | uniq -c | sort -rn | head

À toi

Toutes ces vérifications se pratiquent dans le labo terminal : enquêter et durcir.

À retenir

Pas d'administrateur au quotidien, pas de compte partagé, comptes inutiles désactivés.

Droits minimaux : clé privée et secrets en 600 / 640, jamais de 777.

Désinstaller et arrêter l'inutile.

Mettre à jour automatiquement.

Journaux conservés sur une autre machine.

S'appuyer sur les guides ANSSI et CIS.

Passe à la pratique

Le labo cybersécurité te fait écrire des protections, casser des chiffres faibles et analyser des programmes. Le labo terminal te fait enquêter et durcir un serveur. Et le duel attaque / défense t'oppose à un autre élève.

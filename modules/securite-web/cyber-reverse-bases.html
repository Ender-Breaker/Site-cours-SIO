Cours bonus

Ce cours est hors programme du BTS : il ne compte ni dans ta progression ni au classement. Il est là pour aller plus loin.

La rétro-ingénierie (*reverse engineering*) consiste à étudier un programme déjà compilé pour comprendre ce qu'il fait. C'est le quotidien des analystes qui dissèquent les logiciels malveillants, des auditeurs qui cherchent des failles dans un produit, et une épreuve reine des compétitions de sécurité (CTF).

1. À quoi ça sert, et ce que dit la loi

Le cadre légal

Un logiciel est protégé par le droit d'auteur. Le Code de la propriété intellectuelle (article L122-6-1) n'autorise la décompilation que dans des cas précis, notamment pour l'interopérabilité. Contourner une protection pour utiliser un logiciel sans licence est de la contrefaçon. Tu t'entraînes donc sur tes propres programmes, sur des crackme faits pour cela (crackmes.one, Root-Me, picoCTF) et dans le labo de ce site.

2. Du code source au binaire

source (.c)  ──compilation──▶  code machine (.exe, ELF)  ──▶  exécution par le processeur
source (.java, .cs)  ──▶  bytecode (.class, .dll)  ──▶  exécution par une machine virtuelle
source (.js, .py)  ──▶  interprété tel quel (parfois minifié ou obfusqué)

À la compilation, les noms de variables et les commentaires disparaissent. Il reste des instructions pour le processeur. La rétro-ingénierie remonte le courant :

OutilRemonte vers
Désassembleurl'assembleur : une ligne par instruction machine
Décompilateurun pseudo-code proche du C, à relire avec esprit critique
Débogueurl'exécution pas à pas, avec le contenu des registres et de la mémoire

L'analyse dynamique d'un programme suspect se fait dans une machine virtuelle isolée, sans accès au réseau de l'entreprise, que l'on restaure ensuite à un état sain.

4. La première demi-heure : les outils simples

file suspect.bin             # quel type de fichier est-ce vraiment ?
sha256sum suspect.bin        # son empreinte : est-il déjà connu (VirusTotal) ?
strings -n 6 suspect.bin     # les suites de caractères lisibles
xxd suspect.bin | head       # les premiers octets, en hexadécimal
readelf -h programme         # en-tête d'un exécutable Linux (objdump -d pour désassembler)

strings révèle souvent l'essentiel : messages d'erreur, adresses de serveurs, noms de fichiers, parfois un mot de passe laissé en clair.

5. L'hexadécimal et les octets magiques

Un fichier est une suite d'octets, notés en hexadécimal (00 à FF). L'extension ne prouve rien : le vrai type se lit dans les premiers octets, la signature ou *magic number*.

Premiers octetsEn ASCIIFormat
7F 45 4C 46.ELFexécutable Linux
4D 5AMZexécutable Windows (PE)
89 50 4E 47.PNGimage PNG
FF D8 FFimage JPEG
25 50 44 46%PDFdocument PDF
50 4B 03 04PK..archive ZIP (et donc docx, xlsx, apk, jar)
CA FE BA BEclasse Java
// Un mini « file » : reconnaître un format par sa signature
const signatures = { "7f454c46": "exécutable Linux (ELF)", "4d5a": "exécutable Windows (PE)", "89504e47": "image PNG", "25504446": "document PDF", "504b0304": "archive ZIP" };
function identifier(hex) {
  const h = hex.replace(/\s+/g, "").toLowerCase();
  for (const [sig, nom] of Object.entries(signatures)) if (h.startsWith(sig)) return nom;
  return "inconnu";
}
console.log(identifier("89 50 4E 47 0D 0A 1A 0A"));
console.log(identifier("4D 5A 90 00 03 00"));        // une « facture.pdf » qui commence ainsi est un programme
console.log(identifier("25 50 44 46 2D 31 2E 37"));

6. Lire un vidage hexadécimal

// Un mini « xxd » : adresse, octets en hexadécimal, puis caractères affichables
function vidage(octets) {
  for (let i = 0; i < octets.length; i += 8) {
    const ligne = octets.slice(i, i + 8);
    const hex = ligne.map(o => o.toString(16).padStart(2, "0")).join(" ").padEnd(23);
    const texte = ligne.map(o => o >= 32 && o < 127 ? String.fromCharCode(o) : ".").join("");
    console.log(i.toString(16).padStart(4, "0") + "  " + hex + "  " + texte);
  }
}
vidage([0x7f, 0x45, 0x4c, 0x46, 0x02, 0x01, 0x01, 0x00, 0x6d, 0x64, 0x70, 0x3d, 0x73, 0x69, 0x6f, 0x32, 0x30, 0x32, 0x36, 0x00]);

Et l'équivalent de strings : ne garder que les suites d'au moins 4 caractères affichables.

function chaines(octets, mini = 4) {
  const res = []; let cur = "";
  for (const o of [...octets, 0]) {
    if (o >= 32 && o < 127) cur += String.fromCharCode(o);
    else { if (cur.length >= mini) res.push(cur); cur = ""; }
  }
  return res;
}
console.log(chaines([0x01, 0x02, 0x41, 0x42, 0x00, 0x68, 0x74, 0x74, 0x70, 0x3a, 0x2f, 0x2f, 0x63, 0x32, 0x2e, 0x74, 0x65, 0x73, 0x74, 0x00, 0xff]));

7. Petit-boutiste, gros-boutiste

Un entier sur plusieurs octets peut être rangé dans deux ordres. Les processeurs x86 sont petit-boutistes (*little-endian*) : l'octet de poids faible vient en premier.

ValeurEn mémoire sur x86Dans un paquet réseau (gros-boutiste)
0x1234567878 56 34 1212 34 56 78
const octets = [0x78, 0x56, 0x34, 0x12];
const petit = octets.reduce((v, o, i) => v + o * 256 ** i, 0);
const gros = octets.reduce((v, o) => v * 256 + o, 0);
console.log(petit.toString(16), gros.toString(16));

À retenir

La rétro-ingénierie remonte du binaire vers la compréhension : désassembleur, décompilateur, débogueur.

Statique (lire) et dynamique (exécuter en observant), dans une machine isolée.

Premiers réflexes : file, sha256sum, strings, xxd.

Le type d'un fichier se lit dans ses premiers octets, pas dans son extension.

Cadre légal : ses propres programmes, des crackme d'entraînement, ou une autorisation.

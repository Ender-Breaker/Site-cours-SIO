1. Lire et écrire des fichiers

import java.nio.file.*;
import java.io.IOException;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        Path fichier = Path.of("notes.txt");
        try {
            Files.writeString(fichier, "Léa;15\nSam;9\n");                    // écrit (écrase)
            Files.writeString(fichier, "Zoé;18\n", StandardOpenOption.APPEND); // ajoute à la fin

            List<String> lignes = Files.readAllLines(fichier);                // lit tout
            for (String ligne : lignes) {
                String[] champs = ligne.split(";");
                System.out.println(champs[0] + " a " + Double.parseDouble(champs[1]));
            }
            System.out.println(Files.exists(fichier) + " " + Files.size(fichier));
        } catch (IOException e) {                    // exception vérifiée : obligatoire
            System.out.println("Erreur de fichier : " + e.getMessage());
        }
    }
}

Pour un très gros fichier, on lit ligne par ligne sans tout charger en mémoire :

2. Accéder à une base de données : JDBC

JDBC est l'API standard pour dialoguer avec une base SQL (MySQL, MariaDB, PostgreSQL, SQLite). Le schéma est toujours le même : connexion → requête préparée → résultat.

import java.sql.*;

public class Main {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/parc";
        String sql = "SELECT nom, prix FROM materiel WHERE prix > ? ORDER BY prix";

        try (Connection cnx = DriverManager.getConnection(url, "utilisateur", "motdepasse");
             PreparedStatement requete = cnx.prepareStatement(sql)) {

            requete.setDouble(1, 100);                       // remplace le 1er ?
            try (ResultSet res = requete.executeQuery()) {
                while (res.next()) {                         // une ligne à la fois
                    System.out.println(res.getString("nom") + " : " + res.getDouble("prix"));
                }
            }
        } catch (SQLException e) {
            System.out.println("Erreur SQL : " + e.getMessage());
        }
    }
}

Pour modifier les données : executeUpdate(), qui renvoie le nombre de lignes touchées.

String sql = "INSERT INTO materiel (nom, prix) VALUES (?, ?)";
try (PreparedStatement requete = cnx.prepareStatement(sql)) {
    requete.setString(1, "Écran 27 pouces");
    requete.setDouble(2, 189.90);
    int lignes = requete.executeUpdate();
}
Injection SQL : toujours une requête préparée

Ne construis jamais une requête en collant une saisie de l'utilisateur : "… WHERE nom = '" + saisie + "'". Si quelqu'un tape ' OR '1'='1, la condition devient toujours vraie et il lit toute la table ; il peut aussi détruire des données. Avec PreparedStatement et les ?, la saisie est transmise comme une donnée, jamais comme du code SQL. C'est une exigence du bloc 3 (cybersécurité).

En pratique on range ce code dans une classe DAO (*Data Access Object*) : MaterielDao.trouverTous(), MaterielDao.ajouter(m). Le reste de l'application ne voit jamais de SQL.

3. Maven : construire et gérer les dépendances

Un projet réel utilise des bibliothèques (le pilote MySQL, JUnit…). Maven les télécharge, compile, lance les tests et fabrique le fichier .jar. Tout est décrit dans pom.xml :

<project>
  <modelVersion>4.0.0</modelVersion>
  <groupId>fr.monlycee</groupId>
  <artifactId>parc</artifactId>
  <version>1.0</version>

  <properties>
    <maven.compiler.release>21</maven.compiler.release>
  </properties>

  <dependencies>
    <dependency>
      <groupId>com.mysql</groupId>
      <artifactId>mysql-connector-j</artifactId>
      <version>9.1.0</version>
    </dependency>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.11.0</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>

4. Les tests unitaires avec JUnit

Un test unitaire vérifie automatiquement qu'une méthode renvoie le bon résultat. On l'écrit une fois, on le relance à chaque modification : si un changement casse quelque chose, on le sait tout de suite.

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CompteTest {

    @Test
    void deposerAugmenteLeSolde() {
        Compte c = new Compte("Léa", 100);
        c.deposer(50);
        assertEquals(150, c.getSolde());
    }

    @Test
    void retirerPlusQueLeSoldeEstRefuse() {
        Compte c = new Compte("Léa", 100);
        assertFalse(c.retirer(500));
        assertEquals(100, c.getSolde());             // le solde n'a pas bougé
    }

    @Test
    void soldeInitialNegatifLeveUneException() {
        assertThrows(IllegalArgumentException.class, () -> new Compte("Léa", -1));
    }
}

Un bon test suit trois temps : préparer les données, agir, vérifier. Les objectifs vérifiés automatiquement dans les labos de ce site sont exactement des tests de ce genre.

TutorielArchitecture d'une petite application de gestion

Le modèle : un record

public record Materiel(int id, String nom, double prix) {}

L'accès aux données : un DAO

Tout le SQL est ici, et nulle part ailleurs.

public class MaterielDao {
    private final Connection cnx;
    public MaterielDao(Connection cnx) { this.cnx = cnx; }

    public List<Materiel> trouverTous() throws SQLException {
        List<Materiel> liste = new ArrayList<>();
        try (PreparedStatement r = cnx.prepareStatement("SELECT id, nom, prix FROM materiel");
             ResultSet res = r.executeQuery()) {
            while (res.next()) {
                liste.add(new Materiel(res.getInt("id"), res.getString("nom"), res.getDouble("prix")));
            }
        }
        return liste;
    }
}

La logique : un service testable

Il ne connaît ni le SQL ni l'affichage : on peut le tester avec une simple liste.

public class InventaireService {
    public double valeurTotale(List<Materiel> liste) {
        return liste.stream().mapToDouble(Materiel::prix).sum();
    }
    public List<Materiel> plusChersQue(List<Materiel> liste, double seuil) {
        return liste.stream().filter(m -> m.prix() > seuil).toList();
    }
}

Le programme principal relie le tout

try (Connection cnx = DriverManager.getConnection(url, utilisateur, motDePasse)) {
    List<Materiel> tout = new MaterielDao(cnx).trouverTous();
    InventaireService service = new InventaireService();
    System.out.printf("Valeur du parc : %.2f €%n", service.valeurTotale(tout));
}

Cette séparation modèle / accès aux données / logique / présentation est le principe des architectures en couches et du MVC que tu verras en SLAM.

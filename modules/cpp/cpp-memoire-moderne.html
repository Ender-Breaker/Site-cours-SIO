Le C++ moderne (depuis C++11) permet de ne presque jamais écrire delete. Le principe qui rend cela possible s'appelle RAII.

1. RAII : la ressource vit avec l'objet

*Resource Acquisition Is Initialization* : une ressource (mémoire, fichier, connexion, verrou) est acquise dans le constructeur et libérée dans le destructeur. Comme le destructeur d'une variable locale est toujours appelé à la fin de son bloc, la ressource est toujours libérée, même si on quitte la fonction au milieu.

#include <iostream>
#include <string>
using namespace std;

class Connexion {
    string serveur;
public:
    Connexion(const string& s) : serveur(s) { cout << "connexion à " << serveur << endl; }
    ~Connexion() { cout << "déconnexion de " << serveur << endl; }
    void requete(const string& q) const { cout << "  requête : " << q << endl; }
};

void travail(bool erreur) {
    Connexion c("bdd.local");
    c.requete("SELECT 1");
    if (erreur) return;                 // sortie anticipée : c est quand même détruit
    c.requete("SELECT 2");
}

int main() {
    travail(false);
    travail(true);
}

vector, string, ifstream fonctionnent tous ainsi : c'est pour cela qu'on ne libère jamais leur mémoire à la main.

2. unique_ptr : un seul propriétaire

unique_ptr<T> (bibliothèque <memory>) possède un objet créé sur le tas et le détruit automatiquement. Il ne peut pas être copié, seulement déplacé.

#include <iostream>
#include <memory>
#include <string>
using namespace std;

struct Arme {
    string nom;
    Arme(const string& n) : nom(n) { cout << "création de " << nom << endl; }
    ~Arme() { cout << "destruction de " << nom << endl; }
};

int main() {
    unique_ptr<Arme> a = make_unique<Arme>("épée");     // jamais de new
    cout << a->nom << endl;                              // s'utilise comme un pointeur
    // unique_ptr<Arme> b = a;                           // refusé : copie interdite
    unique_ptr<Arme> b = move(a);                        // transfert de propriété
    cout << (a == nullptr) << " " << b->nom << endl;     // a est vide
    cout << "fin de main" << endl;                       // l'épée est détruite ici, toute seule
}

C'est aussi la bonne façon de stocker des objets polymorphes :

#include <iostream>
#include <memory>
#include <vector>
#include <string>
using namespace std;

struct Forme {
    virtual double aire() const = 0;
    virtual ~Forme() = default;
};
struct Carre : Forme {
    double c;
    Carre(double c) : c(c) {}
    double aire() const override { return c * c; }
};
struct Disque : Forme {
    double r;
    Disque(double r) : r(r) {}
    double aire() const override { return 3.14159 * r * r; }
};

int main() {
    vector<unique_ptr<Forme>> formes;
    formes.push_back(make_unique<Carre>(2));
    formes.push_back(make_unique<Disque>(1));
    for (const auto& f : formes) cout << f->aire() << endl;
    // tout est libéré automatiquement à la fin
}

3. shared_ptr : plusieurs propriétaires

shared_ptr<T> compte ses propriétaires ; l'objet est détruit quand le dernier disparaît.

#include <iostream>
#include <memory>
#include <string>
using namespace std;

struct Texture {
    string fichier;
    Texture(const string& f) : fichier(f) { cout << "chargement de " << fichier << endl; }
    ~Texture() { cout << "libération de " << fichier << endl; }
};

int main() {
    shared_ptr<Texture> a = make_shared<Texture>("herbe.png");
    cout << a.use_count() << endl;            // 1 propriétaire
    {
        shared_ptr<Texture> b = a;            // copie autorisée : 2 propriétaires
        cout << a.use_count() << endl;
    }                                         // b disparaît : retour à 1
    cout << a.use_count() << endl;
    a.reset();                                // plus aucun propriétaire : libération
    cout << "fin" << endl;
}

4. La copie d'un objet

Par défaut, copier un objet copie chacun de ses attributs. C'est parfait… sauf si un attribut est un pointeur brut : les deux objets pointent alors sur la même zone, et chacun la libérera (double libération). D'où la règle de zéro : utilise vector, string et les pointeurs intelligents comme attributs, et tu n'auras aucun destructeur ni constructeur de copie à écrire.

#include <iostream>
#include <vector>
#include <string>
using namespace std;

class Classe {
    string nom;
    vector<string> eleves;         // gère sa mémoire tout seul
public:
    Classe(const string& n) : nom(n) {}
    void ajouter(const string& e) { eleves.push_back(e); }
    size_t effectif() const { return eleves.size(); }
};

int main() {
    Classe a("SIO1");
    a.ajouter("Léa");
    Classe b = a;                      // copie complète et indépendante, sans rien écrire
    b.ajouter("Sam");
    cout << a.effectif() << " " << b.effectif() << endl;
}

5. Déplacer au lieu de copier : std::move

Copier un gros vector recopie tous ses éléments. Le déplacer transfère simplement son contenu vers le destinataire ; l'objet d'origine reste valide, mais vide.

#include <iostream>
#include <vector>
#include <string>
#include <utility>
using namespace std;

int main() {
    vector<string> source = {"a", "b", "c"};
    vector<string> copie = source;              // copie : 3 chaînes recopiées
    vector<string> deplace = move(source);      // déplacement : aucune recopie
    cout << copie.size() << " " << deplace.size() << " " << source.size() << endl;
}
La règle de trois, cinq, zéro

Si ta classe gère elle-même une ressource brute et a besoin d'un destructeur, elle a aussi besoin d'un constructeur de copie et d'un opérateur d'affectation (règle de trois), plus leurs versions par déplacement (règle de cinq). La meilleure solution reste de n'en écrire aucun (règle de zéro).

Le problème avec new

Ce code fuit : l'objet n'est jamais libéré. Le destructeur ne s'affiche pas.

#include <iostream>
#include <string>
using namespace std;

struct Objet {
    string nom;
    Objet(const string& n) : nom(n) {}
    ~Objet() { cout << "destruction de " << nom << endl; }
};

int main() {
    Objet* o = new Objet("potion");
    cout << o->nom << endl;
    // oubli du delete : fuite
}

La solution : unique_ptr

Même code, sans new ni delete : la destruction s'affiche.

#include <iostream>
#include <string>
#include <memory>
using namespace std;

struct Objet {
    string nom;
    Objet(const string& n) : nom(n) {}
    ~Objet() { cout << "destruction de " << nom << endl; }
};

int main() {
    auto o = make_unique<Objet>("potion");
    cout << o->nom << endl;
}

Un sac qui possède ses objets

Retirer un élément du vector le détruit automatiquement.

#include <iostream>
#include <string>
#include <memory>
#include <vector>
using namespace std;

struct Objet {
    string nom;
    Objet(const string& n) : nom(n) {}
    ~Objet() { cout << "destruction de " << nom << endl; }
};

int main() {
    vector<unique_ptr<Objet>> sac;
    sac.push_back(make_unique<Objet>("potion"));
    sac.push_back(make_unique<Objet>("clé"));
    sac.pop_back();                          // la clé est détruite ici
    cout << sac.size() << " objet dans le sac" << endl;
}

À retenir

RAII : acquérir dans le constructeur, libérer dans le destructeur.

make_unique<T>(…) crée un unique_ptr : un propriétaire, pas de copie, std::move pour transférer.

make_shared<T>(…) : propriété partagée, libération au dernier.

Règle de zéro : des attributs qui se gèrent seuls (vector, string, pointeurs intelligents), et rien à écrire.

Dans le navigateur

Le compilateur du site tourne sans disque et sans gestion des exceptions : les exemples d'exceptions et de fichiers de ce chapitre ne sont pas exécutables ici. Ils fonctionnent tels quels sur ton ordinateur avec g++.

1. Les exceptions

Une exception signale une erreur en interrompant le déroulement normal. Elle remonte d'appel en appel jusqu'à un bloc catch capable de la traiter.

#include <iostream>
#include <stdexcept>
using namespace std;

double diviser(double a, double b) {
    if (b == 0) throw invalid_argument("division par zéro");     // lève l'exception
    return a / b;
}

int main() {
    try {
        cout << diviser(10, 2) << endl;
        cout << diviser(1, 0) << endl;        // lève : la suite du bloc try est sautée
        cout << "jamais affiché" << endl;
    } catch (const invalid_argument& e) {     // attrape par référence constante
        cout << "Erreur : " << e.what() << endl;
    } catch (const exception& e) {            // toute autre exception standard
        cout << "Erreur inattendue : " << e.what() << endl;
    }
    cout << "le programme continue" << endl;
}

Toutes dérivent de std::exception et ont une méthode what(). On crée la sienne en héritant de l'une d'elles :

class SoldeInsuffisant : public runtime_error {
public:
    SoldeInsuffisant() : runtime_error("solde insuffisant") {}
};

Grâce à RAII, les destructeurs des objets locaux sont appelés pendant la remontée de l'exception : rien ne fuit. Sans exceptions, on signale une erreur par une valeur de retour, comme dans cet exemple exécutable :

#include <iostream>
#include <optional>
#include <string>
using namespace std;

optional<double> diviser(double a, double b) {        // optional : une valeur, ou rien
    if (b == 0) return nullopt;
    return a / b;
}

int main() {
    for (double b : {2.0, 0.0}) {
        optional<double> r = diviser(10, b);
        if (r) cout << "Résultat : " << *r << endl;
        else cout << "Erreur : division par zéro" << endl;
    }
}

2. Lire et écrire des fichiers

La bibliothèque <fstream> fournit ofstream (écriture) et ifstream (lecture). Ils s'utilisent exactement comme cout et cin.

#include <fstream>
#include <iostream>
#include <string>
using namespace std;

int main() {
    ofstream sortie("scores.txt");               // crée ou écrase le fichier
    if (!sortie) { cerr << "Impossible d'ouvrir le fichier" << endl; return 1; }
    sortie << "Léa 120" << endl;
    sortie << "Sam 95" << endl;
    sortie.close();                              // facultatif : fermé par le destructeur (RAII)

    ifstream entree("scores.txt");
    string nom;
    int score;
    while (entree >> nom >> score) {             // lit tant qu'il y a des données
        cout << nom << " a " << score << " points" << endl;
    }

    ifstream lignes("scores.txt");
    string ligne;
    while (getline(lignes, ligne)) cout << ligne << endl;     // ligne par ligne

    ofstream ajout("scores.txt", ios::app);      // ios::app : ajoute à la fin
    ajout << "Zoé 150" << endl;
}

cerr est la sortie d'erreur ; return 1 dans main signale au système que le programme a échoué. Pour découper une ligne, stringstream transforme une chaîne en flux, et celui-ci est exécutable :

#include <iostream>
#include <sstream>
#include <string>
using namespace std;

int main() {
    string ligne = "Léa 120 15.5";
    stringstream flux(ligne);
    string nom;
    int score;
    double note;
    flux >> nom >> score >> note;
    cout << nom << " | " << score + 1 << " | " << note * 2 << endl;
}

3. Plusieurs fichiers : .h et .cpp

Un vrai projet sépare la déclaration (ce qui existe : fichier d'en-tête .h) de la définition (le code : fichier .cpp).

// ---------- compte.h : la déclaration ----------
#pragma once                       // empêche d'inclure deux fois le même en-tête
#include <string>

class Compte {
    std::string titulaire;         // jamais de « using namespace std » dans un .h
    double solde;
public:
    Compte(const std::string& t, double s);
    void deposer(double montant);
    double getSolde() const;
};
// ---------- compte.cpp : la définition ----------
#include "compte.h"                // guillemets : fichier du projet

Compte::Compte(const std::string& t, double s) : titulaire(t), solde(s) {}
void Compte::deposer(double montant) { solde += montant; }      // Compte:: = « de la classe Compte »
double Compte::getSolde() const { return solde; }
// ---------- main.cpp ----------
#include <iostream>
#include "compte.h"

int main() {
    Compte c("Léa", 100);
    c.deposer(50);
    std::cout << c.getSolde() << std::endl;
}
g++ -Wall -std=c++20 main.cpp compte.cpp -o banque

La construction se fait en deux temps : la compilation transforme chaque .cpp en fichier objet .o, puis l'édition de liens (*link*) les assemble. D'où deux familles d'erreurs : error: … (compilation) et undefined reference to … (édition de liens : la fonction est déclarée mais sa définition n'a pas été fournie).

4. Les espaces de noms

Un namespace regroupe des noms pour éviter les collisions : c'est ce qu'est std.

#include <iostream>
using namespace std;

namespace geometrie {
    const double PI = 3.14159;
    double aireCercle(double r) { return PI * r * r; }
}
namespace finance {
    double aireCercle(double) { return 0; }       // même nom, aucun conflit
}

int main() {
    cout << geometrie::aireCercle(1) << endl;
    using geometrie::PI;                              // n'importe qu'un nom
    cout << PI << endl;
}

5. Automatiser la construction

Dès qu'il y a plusieurs fichiers, on ne tape plus la commande à la main. CMake est l'outil le plus répandu :

# CMakeLists.txt
cmake_minimum_required(VERSION 3.16)
project(Banque CXX)
set(CMAKE_CXX_STANDARD 20)
add_executable(banque main.cpp compte.cpp)
cmake -B build          # prépare
cmake --build build     # compile seulement ce qui a changé
./build/banque

TutorielDécouper un programme en modules

Tout dans un seul fichier

#include <iostream>
using namespace std;

double tva(double ht) { return ht * 0.2; }
double ttc(double ht) { return ht + tva(ht); }

int main() {
    cout << ttc(100) << endl;
}

Ranger dans un espace de noms

Dans un projet, ce bloc deviendrait facture.h (les deux déclarations) et facture.cpp (les deux définitions).

#include <iostream>
using namespace std;

namespace facture {
    double tva(double ht);                 // déclarations : le contenu du futur .h
    double ttc(double ht);
}
namespace facture {
    double tva(double ht) { return ht * 0.2; }      // définitions : le contenu du futur .cpp
    double ttc(double ht) { return ht + tva(ht); }
}

int main() {
    cout << facture::ttc(100) << endl;
}

Chez toi

Crée les trois fichiers facture.h, facture.cpp, main.cpp, puis compile avec g++ main.cpp facture.cpp -o facture. Oublie volontairement facture.cpp dans la commande pour voir l'erreur undefined reference.

À retenir

throw lève une exception, try { … } catch (const exception& e) { … } l'attrape ; e.what() donne le message.

ofstream écrit, ifstream lit, comme cout et cin.

.h = déclarations (avec #pragma once), .cpp = définitions (Classe::methode).

Compilation puis édition de liens ; undefined reference = définition manquante.

namespace évite les conflits de noms.

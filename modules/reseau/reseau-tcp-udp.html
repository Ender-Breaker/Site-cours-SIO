La couche transport fait le lien entre le réseau et les applications. Ses deux protocoles, TCP et UDP, n'ont pas du tout le même caractère : TCP est fiable mais plus lourd, UDP est rapide mais sans garantie. Ce chapitre suit une connexion TCP pendant la consultation d'un site web, montre comment rendre joignable depuis Internet un serveur hébergé dans un LAN privé, puis compare TCP et UDP. Il reprend le TP Packet Tracer du cours (entreprise « Lamartin & Duch », FAI Orange et Free, serveurs Google).

1. Les ports

Un port (nombre de 0 à 65 535) désigne une application dans une machine. Une connexion est identifiée par le quadruplet IP source, port source, IP destination, port destination.

  • Côté serveur : un port connu et fixe (inférieur à 1024), sur lequel il écoute.
  • Côté client : un port éphémère choisi au hasard par le système (au-dessus de 1024 ; Packet Tracer commence à 1025, Windows utilise 49152 à 65535).

2. Les échanges TCP

2.1 Les trois phases

TCP est orienté connexion : avant d'échanger la moindre donnée, le client et le serveur se mettent d'accord. Un échange TCP enchaîne trois phases :

  1. Établissement de la connexion, la « poignée de main en trois temps » (3-way handshake) ;
  2. Échanges : requêtes et réponses, chaque envoi étant acquitté (ACK) ;
  3. Clôture propre de la connexion, à l'initiative du client ou du serveur.

2.2 Le 3-way handshake

Le champ drapeaux (flags) de l'en-tête TCP indique à quelle étape appartient chaque segment :

  1. le client demande l'ouverture : drapeau SYN (synchronisation) ;
  2. le serveur accepte : drapeaux SYN, ACK (synchronisation et accusé de réception) ;
  3. le client confirme : drapeau ACK. La connexion est établie.

2.3 La fiabilité de TCP

Chaque segment porte un numéro de séquence ; le destinataire renvoie un acquittement qui indique ce qu'il a bien reçu. Sans acquittement au bout d'un certain délai, l'émetteur retransmet le segment. C'est ce qu'on observe dans Packet Tracer en supprimant un segment HTTP : il est réémis et la page finit par s'afficher correctement. TCP remet aussi les données dans l'ordre et adapte son débit (contrôle de flux et de congestion).

3. Rendre joignable un serveur privé : le port mapping

L'entreprise Lamartin & Duch héberge son site web sur son propre serveur, d'adresse privée 192.168.1.200. Depuis le LAN, on y accède en tapant cette adresse dans le navigateur. Depuis Internet, impossible : une adresse privée n'est pas routée sur Internet, et l'entreprise n'y est connue que par l'adresse publique de son routeur, 193.252.148.100.

On crée donc sur le routeur une règle de redirection de port (port forwarding, port mapping, NAT statique) : tout ce qui arrive sur l'adresse publique, port 80, est traduit vers 192.168.1.200, port 80.

Router> enable
Router# configure terminal
Router(config)# ip nat inside source static tcp 192.168.1.200 80 193.252.148.100 80

Un internaute (le PC MIO chez Free) peut alors afficher le site en tapant 193.252.148.100. Pour qu'il puisse utiliser le nom www.lamartinandduch.com, on ajoute sur le serveur DNS (8.8.8.8 dans la maquette) un enregistrement qui associe ce nom à l'adresse publique 193.252.148.100.

Piège

Le DNS public doit renvoyer l'adresse publique du routeur, jamais l'adresse privée du serveur : un internaute ne peut rien faire de 192.168.1.200.

4.2 Une requête DNS passe par UDP

En filtrant sur DNS dans Packet Tracer : la requête part d'un port source éphémère du client vers le port 53 du serveur DNS, et la réponse revient directement. Pas de 3-way handshake : une question, une réponse. Si elle se perd, c'est le client DNS qui renverra sa question.

4.4 TFTP : de la fiabilité au-dessus d'UDP

TFTP (Trivial File Transfer Protocol, port 69/UDP) est un transfert de fichiers très simple, sans authentification. On l'utilise pour sauvegarder ou charger la configuration et le système de routeurs et de switchs, ou pour démarrer des postes par le réseau (PXE).

Le client envoie une requête de lecture ; le serveur envoie le fichier en blocs numérotés de 512 octets ; le client acquitte chaque bloc. Si un datagramme se perd, l'acquittement n'arrive pas : au bout d'un délai, le bloc est renvoyé. La fiabilité est donc assurée par l'application TFTP elle-même, et non par UDP.

À retenir
  • Port serveur connu (80, 443, 53…) ; port client éphémère.
  • TCP : SYN → SYN, ACK → ACK, puis échanges acquittés, puis FIN, ACK → FIN, ACK → ACK.
  • Valeurs des drapeaux : FIN 1, SYN 2, RST 4, PSH 8, ACK 16 (SYN, ACK = 18).
  • Port mapping : adresse publique:port → adresse privée:port sur le routeur, et le DNS pointe vers l'adresse publique.
  • TCP = fiable (web, fichiers, e-mail). UDP = rapide (DNS, DHCP, TFTP, voix, vidéo, jeux).

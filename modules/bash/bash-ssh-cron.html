Cours bonus

Ce cours est hors programme du BTS : il ne compte ni dans ta progression ni au classement. Il est là pour aller plus loin.

1. SSH : administrer à distance

SSH ouvre un terminal chiffré sur une machine distante. C'est l'outil quotidien de l'administrateur.

ssh lea@192.168.1.50                 # connexion
ssh -p 2222 lea@serveur.exemple.fr   # sur un autre port que 22
ssh lea@serveur "df -h /"            # exécute une seule commande et revient
exit                                 # ferme la session

2. Les clés SSH

Plutôt qu'un mot de passe, on utilise une paire de clés : la clé privée reste sur ton poste, la clé publique est déposée sur le serveur.

ssh-keygen -t ed25519 -C "lea@portable"     # crée ~/.ssh/id_ed25519 (privée) et .pub (publique)
ssh-copy-id lea@192.168.1.50                # dépose la clé publique sur le serveur
ssh lea@192.168.1.50                        # plus de mot de passe demandé

La clé publique est ajoutée au fichier ~/.ssh/authorized_keys du serveur.

La clé privée ne se partage jamais

Ne l'envoie pas, ne la copie pas dans un dépôt Git, ne la colle dans aucun site. Protège-la par une phrase de passe. Si elle fuit, retire immédiatement la clé publique correspondante de tous les serveurs.

Le fichier ~/.ssh/config évite de retaper les options :

Host web
    HostName 192.168.1.50
    User lea
    Port 2222
ssh web                               # équivaut à ssh -p 2222 lea@192.168.1.50

3. Sécuriser le serveur SSH

Dans /etc/ssh/sshd_config, puis sudo systemctl restart ssh :

PermitRootLogin no               # pas de connexion directe en root
PasswordAuthentication no        # clés uniquement
Port 2222                        # facultatif : réduit le bruit des robots
AllowUsers lea admin             # liste blanche

4. Copier des fichiers

scp rapport.pdf lea@web:/home/lea/              # copie vers le serveur
scp lea@web:/var/log/syslog ./                  # copie depuis le serveur
rsync -avz --delete site/ lea@web:/var/www/site/    # synchronise : ne transfère que les différences

rsync est l'outil des sauvegardes : -a conserve droits et dates, -v détaille, -z compresse, --delete supprime à l'arrivée ce qui a disparu au départ.

5. cron : planifier

crontab -e                       # édite les tâches de l'utilisateur
crontab -l                       # les affiche

Chaque ligne : cinq champs de date, puis la commande.

# minute  heure  jour-du-mois  mois  jour-de-la-semaine   commande
  30      2      *             *     *                    /usr/local/bin/sauvegarde.sh
  0       *      *             *     *                    /usr/local/bin/verif-disque.sh
  */15    *      *             *     *                    /usr/local/bin/ping-serveurs.sh
  0       8      *             *     1-5                  /usr/local/bin/rapport.sh
  0       3      1             *     *                    /usr/local/bin/archivage.sh
ÉcritureSignifie
*toutes les valeurs
*/15toutes les 15 unités
1-5de 1 à 5 (lundi à vendredi)
1,15le 1 et le 15

Lecture : la première ligne s'exécute tous les jours à 2 h 30 ; la troisième toutes les 15 minutes ; la quatrième à 8 h du lundi au vendredi.

Dans cron, l'environnement est minimal

Utilise des chemins absolus pour les commandes et les fichiers, et redirige les sorties vers un journal : … >> /var/log/sauvegarde.log 2>&1.

TutorielUn script de sauvegarde complet

Archiver avec la date dans le nom

#!/bin/bash
set -euo pipefail
SOURCE="/var/www/site"
DESTINATION="/sauvegardes"
ARCHIVE="$DESTINATION/site-$(date +%F).tar.gz"

mkdir -p "$DESTINATION"
tar -czf "$ARCHIVE" -C "$(dirname "$SOURCE")" "$(basename "$SOURCE")"
echo "Archive créée : $ARCHIVE ($(du -h "$ARCHIVE" | cut -f1))"

Supprimer les archives de plus de 7 jours

find "$DESTINATION" -name "site-*.tar.gz" -mtime +7 -delete

Copier sur un autre serveur

Une sauvegarde qui reste sur la même machine n'en est pas une.

rsync -az "$DESTINATION/" sauvegarde@nas:/volume1/sauvegardes/site/

Planifier et journaliser

# crontab -e
30 2 * * * /usr/local/bin/sauvegarde.sh >> /var/log/sauvegarde.log 2>&1

La règle 3-2-1

3 copies des données, sur 2 supports différents, dont 1 hors site. Et une sauvegarde n'existe que si on a testé sa restauration.

À retenir

scp copie, rsync -avz synchronise.

crontab -e : minute, heure, jour du mois, mois, jour de la semaine, commande.

Dans cron : chemins absolus et sortie redirigée vers un journal.

Sauvegardes : règle 3-2-1 et test de restauration.

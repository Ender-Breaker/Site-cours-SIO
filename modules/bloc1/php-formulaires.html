Un formulaire HTML envoie des données à une page PHP, qui les récupère et les traite. C'est la base de toute application web : inscription, connexion, recherche…

1. Le formulaire HTML

<form id="formulaire" action="traitement.php" method="get">

    <input id="test" name="test" type="text" placeholder="TEST" />

    <label for="checkrgpd">J'accepte le RGPD : </label>
    <input id="checkrgpd" name="checkrgpd" type="checkbox" value="accepte" />

    <input id="envoyer" name="envoyer" type="submit" value="Envoyer" />
</form>
ÉlémentRôle
action="traitement.php"page PHP qui reçoit les données
method="get" / "post"get : données visibles dans l'URL ; post : données dans le corps de la requête
name="..."nom du champ : c'est la clé qu'on retrouve côté PHP
<label for="id">texte associé à un champ (clic sur le texte = focus sur le champ)
type="submit"bouton qui envoie le formulaire
name, pas seulement id

Côté PHP, seuls les champs ayant un attribut name sont récupérés.

2. Récupérer les données en PHP

Les valeurs arrivent dans les tableaux $_GET (méthode get) ou $_POST (méthode post), avec le name du champ comme clé.

<?php
ini_set("display_errors", 1);

$nom = $_POST["nom"];          // si method="post"
$age = $_GET["age"];           // si method="get"

Vérifier qu'une donnée existe : isset et empty

<?php
if (isset($_GET["checkrgpd"])) {
    echo "Accepte les conditions";
} else {
    echo "<span style='color: red; background: yellow;'>N'accepte pas les conditions</span>";
}
À retenir

Une case à cocher non cochée n'est pas envoyée : on teste sa présence avec isset($_GET["nom"]).

isset($x) : la variable existe. empty($x) : la variable est vide ou absente.

Ne jamais faire confiance aux données reçues

Avant d'afficher une donnée saisie par l'utilisateur, on la nettoie avec htmlspecialchars($valeur) pour éviter l'injection de code HTML/JavaScript (faille XSS). (Bonne pratique de sécurité, en complément de tes TP.)

3. Formulaire respectant le RGPD (TP)

Le TP demande un formulaire de collecte de données personnelles avec de bonnes pratiques RGPD :

  • un champ nom et un champ prénom (on ne collecte que le nécessaire : minimisation) ;
  • une case à cocher pour accepter la politique de confidentialité (consentement explicite, jamais cochée par défaut) ;
  • un bouton d'envoi ;
  • des <label> associés à chaque champ.

Côté PHP, on refuse le traitement si la case n'est pas cochée.

4. TP de synthèse : abonnement streaming

Le TP combine formulaire, if / elseif / else et switch.

  1. Formulaire : âge, liste déroulante (standard, premium, famille), case « paiement à jour », bouton Valider.
  2. Vérifier que le formulaire a été envoyé et récupérer les valeurs.
  3. Réduction : moins de 18 ans → 20 % ; 18 ans et plus → aucune (if / elseif / else).
  4. Avantages selon l'abonnement (switch) : standard = Vidéo HD ; premium = Vidéo 4K + Téléchargement ; famille = 4 utilisateurs simultanés.
  5. Si le paiement n'est pas à jour : « Accès refusé » ; sinon un récapitulatif complet.
<?php
$age = $_POST["age"];
$abo = $_POST["abonnement"];

if ($age < 18) { $reduction = 20; } else { $reduction = 0; }

switch ($abo) {
    case "standard": $avantages = "Vidéo HD"; break;
    case "premium":  $avantages = "Vidéo 4K + Téléchargement"; break;
    case "famille":  $avantages = "4 utilisateurs simultanés"; break;
    default:         $avantages = "Abonnement inconnu";
}

if (!isset($_POST["paiement"])) {
    echo "Accès refusé";
} else {
    echo "Abonnement $abo : $avantages (réduction : $reduction %)";
}
Résumé express
  • action = page cible, method = get/post, name = clé côté PHP.
  • $_GET["clé"] / $_POST["clé"] récupèrent les valeurs.
  • Case non cochée = non envoyée → isset.
  • RGPD : ne demander que le nécessaire, consentement explicite par case à cocher.

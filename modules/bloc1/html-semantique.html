Le HTML décrit la structure et le sens du contenu d'une page ; le CSS s'occupe de son apparence. Une page bien structurée est mieux comprise par les navigateurs, les moteurs de recherche et les lecteurs d'écran utilisés par les personnes malvoyantes. Ce chapitre complète les bases vues en SLAM (balises, listes, liens, images).

1. Le squelette d'une page

<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Club informatique</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  …contenu visible…
</body>
</html>
ÉlémentRôle
<!DOCTYPE html>Indique au navigateur qu'il s'agit de HTML5 (mode standard).
lang="fr"Langue de la page : prononciation des lecteurs d'écran, traduction automatique, référencement.
<meta charset="utf-8">Encodage des caractères : sans lui, les accents peuvent s'afficher « Ã© ».
<meta name="viewport">Sur téléphone, affiche la page à la largeur de l'écran au lieu d'un bureau miniature.
<title>Titre de l'onglet et des résultats de recherche.
head ou body ?

Le <head> contient les informations sur la page (rien ne s'y affiche) ; le <body> contient ce que l'on voit.

2. Les balises de structure HTML5

Avant HTML5, tout était fait de <div>. Les balises sémantiques disent à quoi sert chaque zone :

BaliseContenu
<header>En-tête : logo, titre du site, souvent le menu.
<nav>Liens de navigation principaux.
<main>Contenu principal de la page, une seule fois par page.
<article>Contenu autonome, qui aurait du sens seul : billet, fiche produit, commentaire.
<section>Partie thématique d'un document, avec un titre.
<aside>Contenu annexe : encadré, liens connexes, publicité.
<footer>Pied de page : mentions légales, contact, copyright.
<body>
  <header>
    <h1>Club informatique</h1>
    <nav>
      <ul>
        <li><a href="index.html">Accueil</a></li>
        <li><a href="contact.html">Contact</a></li>
      </ul>
    </nav>
  </header>
  <main>
    <article>
      <h2>Atelier Raspberry Pi</h2>
      <p>Mercredi, on installe un serveur web.</p>
    </article>
    <aside>…</aside>
  </main>
  <footer>© 2026 Club informatique</footer>
</body>

<div> (bloc) et <span> (en ligne) restent utiles, mais seulement pour la mise en forme, quand aucune balise sémantique ne convient.

3. Le plan : la hiérarchie des titres

  • Un seul <h1> par page : le sujet de la page.
  • Des <h2> pour les grandes parties, des <h3> pour les sous-parties, etc.
  • On ne saute pas de niveau (pas de h4 directement sous un h2).
  • On ne choisit jamais un titre pour sa taille : la taille se règle en CSS.
Pourquoi c'est important

Les lecteurs d'écran permettent de naviguer de titre en titre, et les moteurs de recherche s'appuient sur le plan pour comprendre la page.

4. Liens : internes, ancres, mail, téléphone

<a href="contact.html">Contact</a>                  <!-- page du même site (chemin relatif) -->
<a href="https://www.cnil.fr" target="_blank">CNIL</a>  <!-- autre site, nouvel onglet -->
<a href="#horaires">Voir les horaires</a>             <!-- ancre vers id="horaires" -->
<a href="mailto:club@lycee.fr">Écrire au club</a>
<a href="tel:+33299000000">Appeler</a>

Un chemin relatif part du fichier courant (images/logo.png, ../index.html pour remonter d'un dossier) ; un chemin absolu donne l'URL complète (https://…). Le texte d'un lien doit dire où il mène : « Télécharger le règlement (PDF) » plutôt que « cliquez ici ».

5. Contenus particuliers

<figure>
  <img src="salle.jpg" alt="La salle du club avec dix postes">
  <figcaption>La salle B12</figcaption>
</figure>

<dl>
  <dt>DNS</dt>
  <dd>Service qui traduit un nom de domaine en adresse IP.</dd>
</dl>

<p>Le prix est de 10&nbsp;€ &lt;TTC&gt; — écrire &amp;lt; pour afficher &lt;</p>
  • <figure> + <figcaption> : une illustration et sa légende.
  • <dl>, <dt>, <dd> : liste de définitions (glossaire).
  • Les entités affichent les caractères réservés : &lt; (<), &gt; (>), &amp; (&), &nbsp; (espace insécable).
  • Les commentaires <!-- … --> ne s'affichent pas (mais restent visibles dans le code source : jamais de mot de passe dedans !).
Valider son code

Le validateur du W3C (validator.w3.org) signale les balises mal fermées, les attributs inconnus et les erreurs de structure. Un code valide s'affiche de la même façon dans tous les navigateurs.

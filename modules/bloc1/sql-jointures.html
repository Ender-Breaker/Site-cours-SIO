Les données d'une base relationnelle sont réparties dans plusieurs tables pour éviter de répéter les mêmes informations : le nom du service n'est écrit qu'une fois, dans service, et chaque employé n'en garde que l'identifiant. Pour reconstituer l'information, on fait des jointures. On apprend aussi à calculer des résultats par groupe.

Clé primaire soulignée, clés étrangères en italique.

1. La jointure interne : JOIN … ON

SELECT employe.nom, materiel.modele
FROM materiel
JOIN employe ON materiel.employe_id = employe.id;

Pour chaque matériel, la base cherche l'employé dont l'id est égal à employe_id, et assemble les deux lignes. La condition ON relie presque toujours une clé étrangère à la clé primaire qu'elle référence.

  • Quand deux tables ont une colonne de même nom (nom, id), on préfixe : employe.nom.
  • Des alias de table raccourcissent l'écriture : FROM materiel m JOIN employe e ON m.employe_id = e.id.
  • Un JOIN (ou INNER JOIN) ne garde que les lignes qui ont une correspondance : le matériel non attribué disparaît du résultat.

2. Plusieurs jointures

SELECT i.date_inter, i.motif, m.modele, e.nom
FROM intervention i
JOIN materiel m ON i.materiel_id = m.id
JOIN employe e  ON m.employe_id = e.id
WHERE i.resolue = 0;

On suit le chemin des clés étrangères : intervention → matériel → employé. Le WHERE peut porter sur n'importe quelle table de la jointure.

3. La jointure externe : LEFT JOIN

-- tous les employés, même ceux sans matériel
SELECT e.nom, m.modele
FROM employe e
LEFT JOIN materiel m ON m.employe_id = e.id;

-- seulement les employés SANS matériel
SELECT e.nom
FROM employe e
LEFT JOIN materiel m ON m.employe_id = e.id
WHERE m.id IS NULL;

LEFT JOIN garde toutes les lignes de la table de gauche (celle du FROM) ; quand il n'y a pas de correspondance, les colonnes de droite valent NULL. C'est la technique pour trouver « ceux qui n'ont pas de… ».

Ancienne écriture

On rencontre encore FROM materiel, employe WHERE materiel.employe_id = employe.id. Le résultat est le même qu'un JOIN, mais oublier la condition produit le produit cartésien (chaque ligne avec chaque ligne) : préfère JOIN … ON.

4. Regrouper : GROUP BY

SELECT type, COUNT(*) AS nombre, AVG(prix) AS prix_moyen
FROM materiel
GROUP BY type;

Les lignes qui ont la même valeur de type forment un groupe ; les agrégats sont calculés pour chaque groupe. Règle : dans le SELECT, on ne met que les colonnes du GROUP BY et des agrégats.

-- valeur du matériel par service : jointure + regroupement
SELECT s.nom, SUM(m.prix) AS total
FROM service s
JOIN employe e  ON e.service_id = s.id
JOIN materiel m ON m.employe_id = e.id
GROUP BY s.nom
ORDER BY total DESC;

5. Filtrer les groupes : HAVING

SELECT technicien, SUM(duree) AS minutes
FROM intervention
WHERE date_inter >= '2025-01-01'     -- filtre les LIGNES (avant regroupement)
GROUP BY technicien
HAVING SUM(duree) > 120;             -- filtre les GROUPES (après regroupement)
WHERE ou HAVING ?

WHERE agit sur les lignes, avant le regroupement : il ne peut pas utiliser d'agrégat. HAVING agit sur les groupes, après : c'est là que se met une condition sur COUNT, SUM, AVG…

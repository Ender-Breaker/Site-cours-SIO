Cours bonus

Ce cours est hors programme du BTS : il ne compte ni dans ta progression ni au classement. Il est là pour aller plus loin.

« Ça marche sur ma machine » : Docker supprime ce problème. Il emballe une application avec tout ce dont elle a besoin (bibliothèques, configuration, version exacte de PHP ou de MariaDB) dans un conteneur qui tourne à l'identique partout. Côté SLAM, il donne un environnement de développement en une commande ; côté SISR, il déploie et isole des services.

3. Lancer des conteneurs

docker run hello-world                       # télécharge l'image et lance un conteneur
docker run -d --name web -p 8080:80 nginx    # un serveur web en arrière-plan
OptionRôle
-den arrière-plan (*detached*)
--name webdonne un nom au conteneur
-p 8080:80relie le port 8080 de la machine au port 80 du conteneur
-e CLE=valeurdéfinit une variable d'environnement
-v dossier:/cheminmonte un dossier ou un volume
--rmsupprime le conteneur à son arrêt
-itmode interactif (un terminal)

Après la deuxième commande, http://localhost:8080 affiche la page de nginx.

4. Observer et gérer

docker ps                        # conteneurs en cours
docker ps -a                     # tous, y compris arrêtés
docker logs web                  # ce que le conteneur a affiché
docker logs -f web               # … en continu
docker exec -it web bash         # ouvre un terminal DANS le conteneur
docker stop web                  # arrête
docker start web                 # relance
docker rm web                    # supprime le conteneur
docker images                    # images présentes sur la machine
docker rmi nginx                 # supprime une image
docker system prune              # nettoie ce qui ne sert plus

5. Les données : volumes et montages

Un conteneur est éphémère : quand on le supprime, tout ce qu'il a écrit disparaît. Les données à conserver vont dans un volume.

docker volume create donnees-bdd
docker run -d --name bdd \
  -e MARIADB_ROOT_PASSWORD=secret \
  -v donnees-bdd:/var/lib/mysql \
  mariadb:11

docker run -d -p 8080:80 -v "$(pwd)/site":/usr/share/nginx/html:ro nginx

La seconde commande monte un dossier de ta machine dans le conteneur (:ro : en lecture seule) : tu modifies tes fichiers avec ton éditeur, nginx les sert aussitôt.

6. Les étiquettes de version

docker pull php:8.3-apache       # une version précise
docker pull mariadb:11
docker pull nginx:latest         # « latest » : la plus récente… qui change sans prévenir
Jamais latest en production

L'étiquette latest désigne une version différente selon le jour où tu la télécharges. Fixe toujours une version (mariadb:11.4) : ton déploiement reste reproductible.

TutorielUn serveur web avec ta page

Lancer nginx

docker run -d --name web -p 8080:80 nginx:1.27
docker ps

Regarder à l'intérieur

docker exec -it web bash
ls /usr/share/nginx/html         # la page par défaut est ici
exit

Servir ton propre dossier

docker rm -f web                 # -f : arrête et supprime
mkdir site && echo "<h1>Mon site</h1>" > site/index.html
docker run -d --name web -p 8080:80 -v "$(pwd)/site":/usr/share/nginx/html:ro nginx:1.27

Modifie site/index.html et recharge la page : le changement est immédiat.

À retenir

Image = modèle ; conteneur = instance en cours d'exécution.

docker run -d --name nom -p hôte:conteneur image.

docker ps, docker logs, docker exec -it nom bash, docker stop, docker rm.

Un conteneur est éphémère : les données durables vont dans un volume (-v).

Toujours une version précise, jamais latest.

1. Le Dockerfile : fabriquer sa propre image

Un Dockerfile est la recette d'une image : on part d'une image de base, puis on ajoute ce qu'il faut.

# Dockerfile
FROM php:8.3-apache                      # image de départ

RUN docker-php-ext-install pdo_mysql     # commande exécutée pendant la construction

WORKDIR /var/www/html                    # dossier de travail
COPY src/ .                              # copie le code dans l'image

EXPOSE 80                                # documente le port utilisé
docker build -t mon-site:1.0 .           # construit l'image (le . : dossier courant)
docker run -d -p 8080:80 mon-site:1.0
InstructionRôle
FROMl'image de base
RUNexécute une commande à la construction (installer un paquet)
COPYcopie des fichiers de ta machine dans l'image
WORKDIRfixe le dossier courant
ENVdéfinit une variable d'environnement
EXPOSEindique le port d'écoute
CMDla commande lancée au démarrage du conteneur

Chaque instruction crée une couche mise en cache : place en dernier ce qui change souvent (ton code), pour que les reconstructions soient rapides. Un fichier .dockerignore exclut ce qui ne doit pas entrer dans l'image (.git, node_modules, .env).

2. Docker Compose : plusieurs conteneurs

Une application réelle a plusieurs services : un serveur web, une base de données, parfois un outil d'administration. Docker Compose les décrit dans un seul fichier compose.yaml et les lance ensemble.

# compose.yaml
services:
  web:
    build: .                             # construit l'image depuis le Dockerfile
    ports:
      - "8080:80"
    volumes:
      - ./src:/var/www/html              # le code est modifiable en direct
    depends_on:
      - bdd
    environment:
      DB_HOST: bdd                       # le nom du service sert de nom d'hôte
      DB_NAME: parc
      DB_USER: app
      DB_PASSWORD: ${DB_PASSWORD}        # lu dans le fichier .env

  bdd:
    image: mariadb:11.4
    environment:
      MARIADB_DATABASE: parc
      MARIADB_USER: app
      MARIADB_PASSWORD: ${DB_PASSWORD}
      MARIADB_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
    volumes:
      - donnees:/var/lib/mysql           # les données survivent

  adminer:
    image: adminer:4
    ports:
      - "8081:8080"

volumes:
  donnees:
docker compose up -d             # construit, crée le réseau et lance tout
docker compose ps
docker compose logs -f web
docker compose exec bdd mariadb -u app -p parc
docker compose down              # arrête et supprime les conteneurs (les volumes restent)
docker compose down -v           # … et supprime aussi les volumes
L'indentation compte

Un fichier YAML se structure avec des espaces (jamais de tabulations), deux par niveau. Un décalage d'un espace change le sens du fichier ou le rend invalide.

3. Le réseau entre conteneurs

Compose crée un réseau privé où chaque service est joignable par son nom. Dans le code PHP, l'hôte de la base de données n'est donc pas localhost mais bdd :

$pdo = new PDO("mysql:host=bdd;dbname=parc;charset=utf8mb4", "app", getenv("DB_PASSWORD"));

Seuls les ports listés sous ports: sont accessibles depuis ta machine : ici, la base de données n'est pas exposée à l'extérieur.

4. Les secrets

Les mots de passe ne s'écrivent pas dans compose.yaml (qui est versionné) : ils vont dans un fichier .env, placé à côté et listé dans .gitignore.

# .env (jamais dans Git)
DB_PASSWORD=Un-Mot-De-Passe-Long
DB_ROOT_PASSWORD=Un-Autre-Encore-Plus-Long

Le code

mkdir -p projet/src && cd projet
echo '<?php echo "Bonjour depuis PHP " . PHP_VERSION;' > src/index.php

Le Dockerfile et compose.yaml

# Dockerfile
FROM php:8.3-apache
RUN docker-php-ext-install pdo_mysql
# compose.yaml
services:
  web:
    build: .
    ports: ["8080:80"]
    volumes: ["./src:/var/www/html"]
  bdd:
    image: mariadb:11.4
    environment:
      MARIADB_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
    volumes: ["donnees:/var/lib/mysql"]
volumes:
  donnees:

Lancer

echo "DB_ROOT_PASSWORD=change-moi" > .env
docker compose up -d

Ouvre http://localhost:8080. Un coéquipier qui clone le dépôt obtient exactement le même environnement avec la même commande.

À retenir

Dockerfile : FROM, RUN, COPY, WORKDIR, CMD ; docker build -t nom:version ..

compose.yaml décrit les services, leurs ports, volumes et variables.

docker compose up -d lance tout, docker compose down arrête tout.

Entre conteneurs, on s'appelle par le nom du service.

Les secrets vont dans .env, jamais dans Git.
